# 按风险选择验证

本文提炼可复用的手动检查路径，供维护时按改动选用，不是每次必须执行的完整回归清单。
行为契约以 [Chat 交互设计](chat/chat.interaction.设计文档.md) 和
[Capability 开发指南](capabilities/capability.开发指南.md) 为准；运行命令、数据目录与
GUI 权限限制见 [开发文档](development.md)。历史打包、测试数量和用户反馈不证明当前版本逐项通过。

选测前按本次影响路径核对正式契约、实现和现有回归保护，复用对应复现入口；存量测试不表示本轮已运行或通过。

## 选测与准备

- 实现前写清本次预期、验证方式与主要风险；先判断测试收益，再选择最少有效验证。低耗时能减少返工，或高耗时能显著降低关键风险时值得投入；可不新增或不运行专项测试，仍做必要内容核对与轻量自验。
- 简单文档改动检查内容、链接与 diff；组件交互或桌面交付才按需追加集成、E2E 或打包冒烟。
- 默认使用 Fake Agent、测试数据库和独立 userData；Fake 只证明界面与接线，不证明模型回答、语言遵从或真实 Provider 可用。
- 使用专门测试主题、公司和报告。Capability 安装、更新与删除均限定在测试实例，不能覆盖用户目录或重要资料。
- 真实 LLM/Search 诊断、识别、资料更新与调研按下述每轮额度执行；合理代理 token 与额度内请求已获授权。
- macOS Electron E2E 必须满足开发文档中的 GUI 权限及 sandbox 启动保护；受限时保留未验证项，不绕过保护或反复重试。

每次只选直接相关路径和必要边界；不因本文列出了其他功能而扩大验证范围。

## 测试规模与红灯

先按风险与收益选择独立行为场景，复用现有测试。以下是当轮新增或实质改写逻辑场景的增长复核线，不是每轮目标或硬性任务；无需增加到范围，使用最少有效场景：

| 改动 | 场景参考 |
| --- | --- |
| 文案、文档、纯样式 | 0–2 |
| 普通逻辑 | 0–6 |
| 跨模块、异步、数据安全 | 0–12 |

参数化的不同关键行为分别计数，不靠合成一个 test 隐藏规模。新增场景关联实际改动、缺陷或不变量，按风险组简述成本与独立风险收益即可，无需每个测试单独说明。单一问题优先复用最低成本层的已有测试或复现，只有额外行为风险才补另一层；纯重复断言、实现细节或为覆盖率凑数的测试不新增。E2E 按需选 0–3 条关键旅程，不默认每轮端测。相关存量测试按影响选择，不受新增场景复核线限制，也不要求全部运行。

新增场景超过上述复核线，或普通改动的新增测试编写与维护预计超过当轮开发投入约 20% 时，先重新评估收益，优先缩减重复或改用低成本验证，不机械统计工时。复核线不是禁令；关键高风险可超出，主 Agent 用一句话说明即可，无需追加批准；LLM／Search 每轮额度独立适用。不为普通一次性任务引入新测试框架或重夹具，确有关键风险或持续复用价值时再评估。只保留能长期约束行为的测试，一次性诊断与测试过程通过对话简报记录。

复杂逻辑或可复发缺陷按收益选择红灯保护，可复用既有失败证据或最低成本复现，再修复并重验；纯文案、纯搬迁不走机械 TDD。预期来自需求与契约，不削弱断言以消除失败。连续相同失败先收集诊断、缩小范围再决定重测。代码、环境和输入未变且没有新风险时，不重复已通过检查；目标已有足够证据、剩余测试收益低时停止。未运行的测试如实标明，不能宣称通过。

## 真实端测与每轮额度

主 Agent 可派子 Agent 执行端测，模型遵循 [AGENTS.md](../AGENTS.md)；开发代理模型不替换被测产品当前 LLM 模型。开始前轻量记录目标、路径、预期、停止条件和预计 LLM／Search 次数。使用测试实例、临时数据与现有批准的 Provider，不回显 key，不改用户真实配置或数据。

每轮主／子 Agent 并行执行共用 LLM 20 次、Search 100 次额度，边界包含第 20／100 次，第 21／101 次发出前停止并询问用户。计数对象为 Deepfield 被测程序实际发出的请求 attempt，包含自动重试、循环、后台标题生成以及失败或取消前已发出的请求；Mock 不计，不以 UI 点击数计。开发子 Agent 自身 token 按合理投入另算。不能确认上限可控时，先缩小运行范围或增加测试侧计数限制。费用授权不替代 sandbox／OS 权限。

每轮结束记录实际次数和结果。失败后开始新排查、遇到新问题、修复改码后重测或开始新的调研／端测时，可从零计数并记录新一轮原因，不跨独立轮累计；同一运行中的重试仍计入该轮。重复无变化的自动重试不重置，不凭改名或拆分并行规避额度。

## 设置与联网边界

适用于连接配置、Provider 适配或调用上下文变更。

1. 在测试实例创建或编辑一个 LLM/Search Profile，修改连接字段，先诊断未保存草稿，再保存并设为当前；核对三个操作的状态互不混淆。
2. 编辑已有凭据时留空应保留原凭据；检查正常页面、错误、Chat 和报告均不泄露 key。涉及旧配置迁移时另测迁移路径。
3. 只测本次涉及的协议或 Search Provider 及其选项；失败应给出真实原因，不能悄悄切换其他 Provider。
4. 关闭 Chat 联网后检查没有搜索/网页读取；开启后用一个需要来源的问题核对工具活动与可用来源链接。此开关不代替 Capability 启用状态。
5. 若修改请求配置快照，在任务运行期间切换当前 Profile，再发起一个任务；旧任务保持启动配置，新任务使用新配置。

## Chat 基础与 Skill

适用于输入、流式展示、标题、内置 Skill 或打包资源变更。

1. 启动后直接进入 Chat；Enter 发送，Shift+Enter 换行。流式回复期间打开“公司调研”的研究主题页面再展开 Chat，检查回复持续、消息顺序与滚动正常。
2. Fake 模式检查离线标题与恢复状态；真实模式检查首条消息生成短标题，失败保留 fallback，后续消息不重复生成标题。
3. 真实模式选择 `structured-brief`，用研究笔记检查“核心结论 / 关键依据 / 待核实问题”三节输出；随后不选 Skill 发送普通消息，检查约束解除。打包资源变更时在打包实例复验。
4. 按本次变更选择普通问答、代码解释、写作或跨消息记忆中的相关场景，核对实际回答。Fake 模式不能验证这些效果。

## Chat 历史与人在环中交互

适用于会话、确认、恢复、任务卡或页面联动变更。

1. 新建会话发送消息，切换会话再返回；历史、交互与任务状态属于原消息和原会话，不重复插入结果。
2. 准备一个选择问题，分别用选项或补充文字回应；原会话继续，问题答案不能直接批准后续写操作。
3. 准备一个测试写操作，先取消再重新发起确认；核对目标、影响与真实结果，取消不产生业务对象。
4. 在待确认和后台任务期间切换会话、主动导航或留下未保存输入；迟到结果不抢页面，也不覆盖人工编辑。
5. 重启测试实例检查待办与历史恢复；未确认的写操作不能自行执行，过期入口须说明原因。
6. 修改后台任务路径时，区分停止 Chat 回复与取消任务；只取消指定任务，其他任务继续。启用“完成后分析”时另测原会话分析与新消息优先。

## Capability 启停、表单与授权

适用于加载快照、表单绑定、共同编辑或连续任务变更。

1. 在隔离实例启用/禁用包并重启，核对当前启动快照；禁用后历史仍可读，核心 Chat 仍可用。
2. 通过 Chat 打开本次涉及的真实表单，核对所属业务页面与预填内容；准备草稿本身不得提交业务操作。
3. 用户改一个字段，模型只改另一个字段；两处保留修改。编辑未同步时不能确认旧值，旧版本确认提示重新核对。
4. 按本次涉及的入口选择 Chat 按钮、表单按钮或明确文字确认，检查只执行一次、结果立即可见。取消、条件句与修改意见不能批准旧草稿。
5. 涉及向导时前后切换步骤，检查普通步骤不执行写操作；识别与最终导入分别确认，除非已批准的有限范围明确覆盖对应动作。
6. 涉及连续任务时，先核对已展示的目标、资源消耗与结束条件，再确认一次；范围外动作重新确认，取消、编辑、新任务或重启不能继承旧授权。
7. 未提供可选表单或呈现的包仍能正常调用；不能因缺少页面而虚报操作失败或生成推测的业务页面。

## 公司资料与调研队列

适用于公司导入、共享资料、队列或报告变更；真实调用遵守每轮额度。

1. 导入少量测试公司后立即打开详情；资料更新可继续运行，失败不应把已保存的导入伪装成失败。
2. 从详情更新信息，观察等待、成功和失败状态；运行中不重复提交，失败保留人工字段与来源。涉及主体修正时核对其他主题共享资料。
3. 在资料待更新、更新中或失败时准备单家/批量调研，检查可提交且已有队列项不重复入队；只在最终批准后执行。
4. 用少量公司核对队列进度、失败反馈与取消；限定取消本次任务，已完成结果和其他独立任务保留。
5. 从 Chat 读取已有报告并打开对应版本，不额外创建调研；切换会话后仍可查询同一任务和结果。
6. 涉及报告重试时区分原始调研与结构化整理；输入未变的结构化重试保留原始报告，不重新联网调研。
7. 涉及导出时选择需要的报告内容，核对系统保存对话框；取消保存显示取消，不显示成功。

### 研究主题与公司导入

适用于列表、识别或导入流程变更。从“公司调研”的“研究主题”页面进入测试主题：

1. 创建、编辑主题和公司，进入公司详情再返回；单条与批量删除分别先取消再确认，核对影响范围。
2. 用 Fake recognizer 识别、编辑候选并导入，检查保存结果与详情入口。涉及真实识别行为时按每轮额度补验。
3. 识别分块或重试变更时，使用超过 4000 code points 的多块文本，检查失败保留成功候选、重试不重复成功请求；超过 48000 code points 时在请求前显示长度错误。

### 报告版本与两阶段恢复

适用于调研执行、版本、取消或报告呈现变更。使用现有批准的真实 LLM / Search 配置并遵守每轮额度：

1. 从“公司调研 → 研究主题 → 主题 → 公司详情”完成一次调研；调整时间范围或补充要求再运行，检查新报告默认展示，旧报告仍可切回。
2. 调研期间使用 Chat、关闭能力页面再返回，检查后台任务继续、进度与草稿恢复。
3. 分别检查原始报告和结构化报告、HTTP/HTTPS 来源与所需 Word 导出内容。涉及质量验收时记录用途、耗时、长度与来源反馈，重要事实由人工核实。
4. 原始调研失败与结构化整理失败应显示对应恢复入口；输入未变的结构化重试只整理已有原始报告，输入变化后重新调研。
5. 取消本轮未完成调研移除该轮记录，保留既有成功版本；失败记录保留供重试。

## 留下可复现证据

记录当前应用/能力版本、测试模式、所选路径、预期与实际结果，以及必要的会话/操作上下文；不保存密钥或敏感内容。
失败时记录停下的步骤、错误原因与已完成效果，避免在结果未知时重放写操作。
上述过程、结果、每轮实际请求次数及新一轮原因均记录在对话简报中供用户审核，无需另建测试报告、计划、派工或复核文件；测试发现问题后，主 Agent 无需用户再次提醒，持续定位、修复并重测至可阶段交付，受权限或额度等实际阻塞时在对话说明。必要的代码回归测试、正常产品诊断日志及正式架构文档仍按原约定维护，已有历史文件保留；交付说明明确未执行的真实调用、GUI 或自然语言验证。
