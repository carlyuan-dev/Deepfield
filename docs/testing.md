# 按风险选择验证

本文提炼可复用的手动检查路径，供维护时按改动选用，不是每次必须执行的完整回归清单。
行为契约以 [Chat 交互设计](chat/chat.interaction.设计文档.md) 和
[Capability 开发指南](capabilities/capability.开发指南.md) 为准；运行命令、数据目录与
GUI 权限限制见 [开发文档](development.md)。历史打包、测试数量和用户反馈不证明当前版本逐项通过。

## 选测与准备

- 实现前写清本次预期、验证方式与主要风险；优先聚焦测试，再补自动测试不能证明的实际页面路径。
- 简单文档改动检查内容、链接与 diff；组件交互或桌面交付才按需追加集成、E2E 或打包冒烟。
- 默认使用 Fake Agent、测试数据库和独立 userData；Fake 只证明界面与接线，不证明模型回答、语言遵从或真实 Provider 可用。
- 使用专门测试主题、公司和报告。Capability 安装、更新与删除均限定在测试实例，不能覆盖用户目录或重要资料。
- 真实 LLM/Search 诊断、识别、资料更新与调研可能联网并收费，只有用户已授权对应调用与费用后才执行；未获授权时记录未验证。
- macOS Electron E2E 必须满足开发文档中的 GUI 权限及 sandbox 启动保护；受限时保留未验证项，不绕过保护或反复重试。

每次只选直接相关路径和必要边界；不因本文列出了其他功能而扩大验证范围。

## 设置与联网边界

适用于连接配置、Provider 适配或调用上下文变更。

1. 在测试实例创建或编辑一个 LLM/Search Profile，修改连接字段，先诊断未保存草稿，再保存并设为当前；核对三个操作的状态互不混淆。
2. 编辑已有凭据时留空应保留原凭据；检查正常页面、错误、Chat 和报告均不泄露 key。涉及旧配置迁移时另测迁移路径。
3. 只测本次涉及的协议或 Search Provider 及其选项；失败应给出真实原因，不能悄悄切换其他 Provider。
4. 关闭 Chat 联网后检查没有搜索/网页读取；开启后用一个需要来源的问题核对工具活动与可用来源链接。此开关不代替 Capability 启用状态。
5. 若修改请求配置快照，在任务运行期间切换当前 Profile，再发起一个任务；旧任务保持启动配置，新任务使用新配置。

## Chat 历史与人在环中交互

适用于会话、确认、恢复、任务卡或页面联动变更。

1. 新建会话发送消息，切换会话再返回；历史、交互与任务状态属于原消息和原会话，不重复插入结果。
2. 准备一个选择问题，分别用选项或补充文字回应；原会话继续，问题答案不能直接批准后续写操作。
3. 准备一个测试写操作，先取消再重新发起确认；核对目标、影响与真实结果，取消不产生业务对象。
4. 在待确认和后台任务期间切换会话、主动导航或留下未保存输入；迟到结果不抢页面，也不覆盖人工编辑。
5. 重启测试实例检查待办与历史恢复；未确认的写操作不能自行执行，过期入口须说明原因。
6. 修改后台任务路径时，区分停止 Chat 回复与取消任务；只取消指定任务，其他任务继续。启用“完成后分析”时另测原会话分析与新消息优先。

## Capability 启停、表单与授权

适用于加载快照、表单绑定、共同编辑或连续任务变更。

1. 在隔离实例启用/禁用包并重启，核对当前启动快照；禁用后历史仍可读，核心 Chat 仍可用。
2. 通过 Chat 打开本次涉及的真实表单，核对所属业务页面与预填内容；准备草稿本身不得提交业务操作。
3. 用户改一个字段，模型只改另一个字段；两处保留修改。编辑未同步时不能确认旧值，旧版本确认提示重新核对。
4. 按本次涉及的入口选择 Chat 按钮、表单按钮或明确文字确认，检查只执行一次、结果立即可见。取消、条件句与修改意见不能批准旧草稿。
5. 涉及向导时前后切换步骤，检查普通步骤不执行写操作；识别与最终导入分别确认，除非已批准的有限范围明确覆盖对应动作。
6. 涉及连续任务时，先核对已展示的目标、资源消耗与结束条件，再确认一次；范围外动作重新确认，取消、编辑、新任务或重启不能继承旧授权。
7. 未提供可选表单或呈现的包仍能正常调用；不能因缺少页面而虚报操作失败或生成推测的业务页面。

## 公司资料与调研队列

适用于公司导入、共享资料、队列或报告变更；真实调用遵守费用授权。

1. 导入少量测试公司后立即打开详情；资料更新可继续运行，失败不应把已保存的导入伪装成失败。
2. 从详情更新信息，观察等待、成功和失败状态；运行中不重复提交，失败保留人工字段与来源。涉及主体修正时核对其他主题共享资料。
3. 在资料待更新、更新中或失败时准备单家/批量调研，检查可提交且已有队列项不重复入队；只在最终批准后执行。
4. 用少量公司核对队列进度、失败反馈与取消；限定取消本次任务，已完成结果和其他独立任务保留。
5. 从 Chat 读取已有报告并打开对应版本，不额外创建调研；切换会话后仍可查询同一任务和结果。
6. 涉及报告重试时区分原始调研与结构化整理；输入未变的结构化重试保留原始报告，不重新联网调研。
7. 涉及导出时选择需要的报告内容，核对系统保存对话框；取消保存显示取消，不显示成功。

## 留下可复现证据

记录当前应用/能力版本、测试模式、所选路径、预期与实际结果，以及必要的会话/操作上下文；不保存密钥或敏感内容。
失败时记录停下的步骤、错误原因与已完成效果，避免在结果未知时重放写操作。
将本轮过程记录留在本地；长期文档仅更新稳定契约与可复用步骤。交付说明明确未执行的真实调用、GUI 或自然语言验证。
