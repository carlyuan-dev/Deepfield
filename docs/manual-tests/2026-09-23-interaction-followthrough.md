# Chat / Capability 交互闭环手测

状态：已完成开发、定向测试、独立复核及 macOS arm64 打包，待用户手测。公司调研包 2.3.0 已同步到实际加载目录。使用新建的测试主题，不删除已有真实资料。

测试应用：`release/mac-arm64/Deepfield.app`。本轮未执行真实模型/搜索请求，未修改用户业务数据。

## 1. 页面与表单

1. 从任意公司详情发消息：`新建主题“交互测试”，其他内容留空。`
2. 右侧应先到研究主题首页再打开真实新建表单；左侧 Chat 可操作。修改主题名后，分别尝试右侧确认、Chat 确认及 `确认无误`；每次只创建一个主题。
3. 成功后进入新主题，返回首页可看到新条目，无需重启或手动刷新。
4. 请求删除这个测试主题：右侧应显示主题首页和原生删除确认框，明确显示待删主题名称。先取消验证不删除，再重新发起并确认；左右按钮共用同一次确认，完成后列表立即更新。移除公司、删除报告也应显示准确目标。
5. 在已有主题请求添加公司、移除一个测试公司、准备批量调研：应先进入相应主题公司列表，不在无关页面上直接弹窗。

## 2. 交互展示

1. 同一操作只保留一份完成结果和结果入口，不出现两张重复卡。
2. 请模型给出几个导入范围供选择：上方短问题、下方选项框，悬停高亮，仍可输入自定义答案。
3. 回答后保留紧凑的问题/答案记录，不显示重复长段落。切换会话再回来记录仍在。
4. 右侧编辑期间，Chat 不应提交旧字段；用户切换其他页面后，迟到事件不应强行拉回。

## 3. 本次任务授权

1. 在新建测试主题要求添加四个已知公司。应先出现具体待确认卡，显示目标主题、全部四个名称及“新公司可能自动调用模型和搜索补全资料”；不要额外识别已经明确的名称。回复 `可以，补进去，你一路确认就行，不要我来点`，应执行一次添加，不再要求点击。
2. 多项具体操作使用 `propose_actions` 时，确认前应在同一卡完整列出全部操作（最多 10 项、同一能力与声明类别）。分别用 Chat 按钮、右侧表单确认、`确认无误`、`本次一路确认` 验证：都执行同一份已展示清单，每项一次，不只执行第一项。普通单项确认仍只执行当前单项。
3. 编辑第一项内容后旧版本确认不得执行；待同步完成，卡片显示更新内容，重新确认才执行更新后的清单。执行期间发新消息或取消，尚未发出的其余项停止；已经发出的动作按真实回执显示，不声称回滚。
4. 原清单结束后追加第五家公司、改到其他主题、移除公司或提交调研，应重新准备并确认。识别文本新得到的候选未在原提案中明确列出时，添加仍须确认。
5. 重启后提案可保留，但不自动执行；再次明确确认才可执行。只有历史口头建议、没有当前具体提案时说 `本次一路确认`，应先准备具体提案，再请用户文字确认一次；不声称已获得后续任意操作授权。
6. 正在回答范围问题时输入 `本次一路确认` 只算问题答案。`他说“本次一路确认”`、`不要本次一路确认`、`如果没问题，本次一路确认`、`本次一路确认，但先改名字` 不自动批准。本次实现采用完整明确短句，不声称理解所有授权表达。

## 4. 公司资料补全

1. 在“大模型”主题重试月之暗面：观察资料补全结果及失败时的具体提示。此次修改应避免通过重复抄写 URL 引入括号丢失等错误，但仍以真实来源为依据。
2. 重试百度文心：检查识别的公司主体与品牌/产品关系，法定名称及总部仅在找到对应证据时填写，不用产品名称冒充公司法定名称。
3. 检查华为等既有公司正常复用，不因本轮变更覆盖用户手工填写资料或改变过往报告。

## 5. 通用边界

1. 重启后未启用 Capability 时，普通 Chat 和提问确认仍可用。
2. 不提供表单/导航扩展的包，仍按原协议调用，缺少可选展示不导致主 Agent 失败。
3. 正常回答保持中文；无需输出英文执行旁白和内部标识符。
