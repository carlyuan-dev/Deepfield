# 0.1.3 版本收口（2026-11-05）

应用版本 0.1.3，公司调研包 4.0.1。基于 0.1.2 稳定版整理 Base.Trace 及其接线，以 `v0.1.3` 标签定位正式发布源码。交付流程为 `develop` 开发与验收，通过后合入 `main`；日常测试包不单独创建发布标签。

## 本轮内容

- Base.Trace 为 Chat、模型、工具、Capability 动作及后台阶段提供执行关联、终态与错误定位。模型调用在 Base.Model 收拢，Usage 继续作为唯一用量账本。
- 宿主支持跨 Worker 上下文、独立本地存储、容量与保留期控制；观测缺失或异常不阻断业务。默认只采集元数据，正文须逐请求显式授权。
- Capability 通过可选 `trace.v1` 接入，公司调研关联队列任务、原始调研、结构化整理及产物；提供只读 CLI 与可选 Phoenix 导出。
- Fake 模式的标题生成保持本地处理，避免测试路径意外发送标题模型请求。

完整契约见 [Base.Trace](../base/base.trace.设计文档.md)，接入方式见 [Capability 开发指南](../capabilities/capability.开发指南.md#可选执行追踪)。

## 验证范围

独立代码复核未发现明确发布阻断缺陷；类型检查、构建及 arm64 打包通过。默认 Vitest 共 297 个文件、2604 项通过、2 项跳过；拆分时出现的两文件旧契约夹具问题已对齐稳定基线，并对相关 22 项复验通过，其余已通过检查未重复执行。

最终打包应用在独立 userData 下完成两组 Electron 验证：

- Fake：Chat 完成，公司调研原始／结构化阶段完成并关联产物；无模型 span 或 Usage 请求记录。
- 真实协议、本机 HTTPS 模拟上游：4 次请求对应 4 个模型 span、4 条唯一 Usage 关联；两次工具执行及一次 Capability 动作完成，跨两个进程会话。原生工具没有统一的业务成功契约，终态按设计为 unknown，动作与请求的成功单独验证。
- 两组均未开启正文采集，正文数据库未创建；隔离实例结束后清理。应用内版本与公司包版本分别核对为 0.1.3、4.0.1。

本轮未配置或调用外部付费 LLM／Search；上述验证覆盖本地采集与协议接线，不外推真实模型回答质量或外部 Provider 可用性。正文权限、脱敏、IPC 归属、容量与导出由对应离线测试约束。本地安装包为未正式签名构建，公开分发仍需签名与公证。

已有用户安装的能力包不会被内置副本自动覆盖。需要公司调研包内阶段追踪时，退出应用后按开发指南更新至完整的 4.0.1 包并保留旧包备份；原有数据与配置沿现有规则保留。Trace 是独立诊断存储，代码版本标签不代替用户数据备份或降级兼容检查。
