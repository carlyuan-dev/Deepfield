## 1. 目标与非目标

开发者交付一个自包含、兼容宿主的预构建包，无需修改 Chat 源码，即可让用户通过页面、模型通过声明的操作使用同一业务。模型只依赖本次可用目录、操作契约和使用说明，不依赖页面布局或包源码。

本批不做 DOM 点击、截图驱动、任意 JavaScript 执行、热插拔、在线更新、插件市场、跨包依赖、独立调度平台或 Base.Storage/Base.Agent 迁移。业务按钮应有对应公开动作、任务控制或导航入口；纯页面交互不机械转换为点击工具。

### 1.1 领域无关是硬约束

Capability 不限定业务方向。调研、填表、业务流程、工单入库与查询均只是解释用例，不构成支持范围、业务分类或准入名单；未来未知业务也应能通过相同调用边界接入。公共协议不设业务类型枚举，不按场景写分支，只认识包、动作、输入输出、可选页面/草稿/任务/产物；companyId、研究方向、报告章节、Search 和两轮调研均属于具体包，不能成为公共必填字段或内置流程。

扩展原则：新业务优先新增包自己的动作、输入输出 Schema、文档与实现，不修改 Chat 或宿主业务分支。只有出现现有协议无法表达的通用交互需求时，才通过版本化公共协议扩展；具体业务状态、数据模型与步骤留在包内。协议的范围约束是接口兼容、宿主实际提供的资源和用户授权，不是业务方向。通用性不等于预先加入所有未来功能，也不承诺任意程序无需适配即可运行。

| 业务示例 | 公共协议用法 | 不要求实现的部分 |
| --- | --- | --- |
| 工单库查询 | 即时只读动作返回匹配记录及引用；大量结果分页 | 不要求 UI、后台任务、联网或 LLM |
| 表单填写 | 生成草稿、可选预览页面、确认后提交写操作 | 不要求队列、报告或来源网址 |
| 业务流程 | 创建任务、查询状态，通过包声明的后续动作提交补充信息 | 不要求调研阶段；等待人工输入可投影为 paused 并带 reason |
| 公司调研 | 付费任务、专属队列和 Harness、报告产物与页面 | 只作为完整适配案例，不定义通用协议形状 |

只有公开动作是模型调用包的基本要求。UI、草稿、任务、持久产物和 LLM/Search 均可选；不使用 Worker 的 v2 包不必提供空 Worker 入口。宿主按包声明的支持面提供功能，不支持的可选请求明确返回 unsupported。协议通用不意味着宿主预先支持所有外部系统或业务权限；新需求通过版本化宿主服务扩展，包不得越过当前授权。

## 2. 设计起点与本批增量

下表记录制定协议时的基线，不表示当前实现仍停留在该状态。公司包最初以 5 个动作完成第二阶段验收；第三阶段 Chat 接线与持久关联已实现，本轮在同一协议上补齐主题、公司、队列、报告和导出的业务动作，不另建业务执行流程。

| 能力 | 设计时基线 | 本批增量 |
| --- | --- | --- |
| 包扫描、启动快照、启停、故障隔离 | main/capabilities 与第一、二批验收 | 复用，不新增另一套扫描 |
| 操作声明 | SDK manifest 已有 actions；公司调研 actions 为空 | 登记可供 Chat 使用的动作与说明 |
| UI 通用通信与输入输出校验 | SDK CapabilityBridge、CapabilityRegistrar | 复用传输；增加公共动作分发与可信调用上下文 |
| 公司调研与队列 | 包内 application、现有统一队列 | 包适配动作、任务与产物；不复制业务流程 |
| 模型工具执行 | 已安装 Pi 的 AgentTool.execute、工具事件与执行策略 | 注册通用 Capability 工具，不另写 Loop |
| 页面导航 | 包首页入口与包内 React 状态 | 声明式目标、草稿交接和 UI 接收反馈 |
| Chat 任务关联与文档缓存 | 本批未实现 | 会话持久关联、按版本复用、结果按需读取 |

本文描述协议契约；可运行接口以 SDK 与开发指南为准。现有内部 operation 不能因为名称存在就自动成为公开 action。

### 可选 Chat 表单绑定（本次扩展）

已启用且 ready 的 v2 包可调用 `registrar.registerFormProvider(definitions, provider)`。每个定义用稳定 `id`、本包已登记公开动作的 `actionIds` 和短说明绑定原有表单；未登记的旧动作仍可调用，需确认时使用只读审批摘要。无包时 Chat 的提问仍可用。无效的可选表单声明只失效对应编辑入口，不能授权或代替动作声明；运行期只发布有效绑定。

表单内容只有包内一份草稿。提供方的 `prepare/read/update/transition/validate/submission/release` 负责草稿、校验和最终输入；宿主协调器只保存草稿引用、会话归属、修订与回应。`update` 和步骤转换须基于预期修订；用户开始输入时立即调用绑定桥的 `beginEdit` 锁住确认，两侧旧修订均不能执行。提交前重新读取、校验并冻结最终动作输入，再由宿主动作网关签发单次确认许可。模型可读取或改草稿，不能传入批准来源；左右按钮及可信用户文字回应走同一个宿主决定入口。

可选 `afterAction` 在真实成功回执后推进同一草稿并声明下一公开动作；下一阶段必须创建新的确认，上一批准不能沿用。包 UI 只取得绑定当前待办和本包的 `CapabilityInteractionEditor`，没有任选会话的写入接口或批准票据。此协议要求包作者实际实现并维护动作、草稿、ViewRef 与真实 UI 的对应；不自动识别任意页面。当前离线便签夹具覆盖一个符合接口的包，不能据此宣称任意现有包自动兼容。

包草稿推进与 Chat 下一阶段描述符不是跨存储原子提交。真实动作成功后的极窄崩溃窗口应保留可核对的原动作结果，不能为了补阶段自动重放写操作；需重新核对表单与回执后继续。

## 3. 责任划分

```text
Chat → 统一工具适配 → 公共动作网关 ← UI 操作入口
                         ↓
                  Capability 业务服务
                         ↓
                  任务 / 数据 / 报告

Chat → 宿主页面导航 → Capability 页面（展示、草稿、人工确认）
```

- 通用 Agent：执行注入工具与处理工具结果，不扫描包、不识别公司调研。
- Chat：会话、说明复用、任务关联、用户意图与最终分析。
- 宿主：启动目录、调用者身份、校验、授权/确认、分发、页面导航和安全投影。
- Capability：操作定义、业务 Harness、队列、草稿、数据、结果与页面解析。
- 公共模型/Search 路径：继续统一记录 Usage；Chat 与界面发起的同类任务走同一计量路径。

两个入口共用业务规则与关键校验，不要求内部所有只读 UI 接口立即迁成公共动作。但已对 Chat 暴露的写操作，其对应 UI 提交须经过同一动作服务或同一受保护业务入口，不能各写一套校验、确认或排队逻辑。

## 4. 启动可用性与授权

1. 启动扫描与配置生成不可变快照，只发布其中成功 ready 的包及其公开动作。
2. 设置勾选变化只影响下次启动；本次不新增、移除或升级动作。
3. ready 包发生运行故障时，调用可暂时不可用，宿主返回真实错误；这不是动态加载。历史说明不能绕过就绪检查。
4. 无可调用包时，不向模型注入 Capability 目录或本协议工具；历史调用记录照常可读。
5. 包更新在应用退出时进行，重启后生效。运行时覆盖包文件不属于支持范围；检测到契约变更拒绝使用混合版本，提示重启。

“本次启用”不等于拥有任意权限。有效权限为宿主授予的操作权限与包声明要求的交集。调用者、会话 ID、权限和确认凭据由宿主提供，不接受模型自报。

Chat 的联网按钮控制该轮直接使用的搜索工具，不决定公司调研业务自身的联网规则。调研动作必须明确说明会调用 LLM/Search 并产生消耗，遵循自身 Harness；用户明确要求不联网时，Chat 不应通过该动作绕开意图，应解释冲突或仅读取既有报告。

## 5. 操作契约：一份定义，多处使用

建议包内维护 `actions/` 操作定义和 `docs/actions/` 使用说明，文件名不是强制目录约束。规范约束的是清单与产物，不是开发者源码写法。

开发者交付 Capability 时应提供面向用户的说明；v2 清单字段 `help` 可选仅为兼容旧包，缺失不阻止加载。新包应声明包内相对路径 `help`，指向随包分发的 UTF-8 Markdown 用户介绍（例如 `docs/help.md`）。它应说明可做的事、可获得的结果和自然语言示例，与模型按需读取的 `docs/actions/` 操作契约分离。`/help` 和只读“查看可用功能”工具仅展示本次已启用且 ready 包的帮助；缺失、空白或不安全的帮助文件只显示包名，不从动作 ID、Schema 或描述拼装技术目录。帮助正文不逐轮注入系统提示。机器参数用于内部调用，普通答复展示用户可理解的名称、动作与真实结果；用户明确索取技术细节时除外。

每个动作定义：

| 字段 | 含义 |
| --- | --- |
| id / title / description | 稳定 ID、展示名、一句话用途；不使用按钮坐标或 DOM 名称 |
| inputSchema / outputSchema | 受支持 JSON Schema 子集；outputSchema 描述成功业务数据，不重复定义通用错误信封 |
| mode | immediate 或 task；创建后台任务须快速返回，不等待完整研究完成 |
| effects | read / write / destructive 表示对业务数据的影响；consumesResources 独立标记资源消耗。只读查询可使用计费检索/模型，但必须如实声明，不得隐式写入业务数据 |
| permissions / requiresConfirmation | 声明执行要求；宿主可施加更严格限制，包不能降低 |
| documentation | 包内说明路径、版本和构建生成的内容摘要 |
| handler | 包内实际执行函数，仅运行时注册，不序列化进清单 |

构建工具从同一操作定义导出非执行清单与 Schema，运行时注册同一份定义，避免手写两套参数。说明由作者维护，构建时检查文件存在、路径合法、重复 ID、Schema 合法与声明/注册对应；它不能证明业务描述准确。

输入校验后进入业务服务，输出也校验。字段错误应指出字段和约束；不得默默丢弃未知参数、替模型补造公司 ID 或截止日期。合法的业务默认值须写进说明与回显的实际参数。

业务对象不唯一时返回候选项，Chat 查询或向用户澄清；例如公司、客户或工单名字相似时，不能直接猜测执行。

## 6. 模型入口与渐进说明

本批采用少量通用工具，不为每个包动态制造一组专属工具：

| 工具 | 职责 |
| --- | --- |
| capability_describe | 按 capabilityId/actionId 读取完整说明、Schema、执行影响和契约摘要 |
| capability_invoke | 按 actionId 调用已声明业务动作，输入经过内层 Schema 校验 |
| capability_task | 查询或明确取消一个任务；不提供无限轮询和任意批次取消 |
| capability_read | 按产物引用读取摘要、目录或指定内容切片 |
| capability_open | 打开声明的页面目标，或展示已准备好的草稿 |

模型首先收到精简目录：包 ID/名称、操作 ID/用途与影响标记，不注入完整手册。目录来自启动快照。操作说明读取后才允许本会话调用该动作；直接猜 ID 不跳过说明与授权。

describe 缓存键包括会话、包 ID、包版本、动作 ID 和契约/说明摘要。重复读取不重复追加整份文本；上下文压缩后由 Chat 恢复当前相关说明。重启后重新核对快照，新版本使旧缓存失效；不重放旧写操作。

Pi 负责工具调用、AbortSignal 与事件；本协议工具提供适配。首版公共 invoke 按顺序执行，避免同轮写操作竞争；长任务入队后即返回，不占住工具调用。结果与说明视为业务数据，不得覆盖系统指令或权限。

## 7. 统一调用与返回

模型传 capabilityId、actionId、input、describe 得到的 contractDigest。宿主补充 invocationId、调用来源、会话关联和确认信息，并检查当前快照。摘要只是版本标识，不是授权凭据。

返回使用可判别的公共信封：

- `completed`：data（通过该动作 outputSchema 校验）、可选 artifactRefs/viewRefs。
- `accepted`：taskRef、当前公共状态与简短说明；仅表示接收，不表示业务成功。
- `requires_confirmation`：宿主确认项引用与实际参数摘要；此时尚未执行业务。
- `error`：安全 code/message/retryable、字段错误或恢复建议，可附已创建的 taskRef 供核对。

信封包含 capabilityId/actionId、包版本、contractDigest、invocationId。结构错误、权限错误、配置错误、执行失败分别映射现有 AppError，不统一伪装成 Search 或模型失败。日志不得暴露 Key、原始请求头或任意堆栈。

确认由真实 UI 操作生成，绑定动作、规范化参数和契约版本；修改任一项须重新确认。首版读取、普通导航不确认；付费调研提交提供一次确认摘要，可复用预填表单的“开始调研”。用户从该表单提交不再重复弹窗。删除、覆盖和文件导出另遵循现有可信确认/保存流程，不接受模型传入 `confirmed: true`。

## 8. 页面联动：打开、草稿、执行分开

包声明公开 viewId 与参数 Schema，并提供包内解析器。宿主只知道“打开该包的该目标”，不写公司页面的 if/else，也不接收模型给出的任意 URL、文件路径或 JavaScript。

- **打开结果**：目标包含业务 ID 与明确报告版本，包确认存在后导航。
- **准备输入**：包的准备动作生成 draftRef；草稿保存规范化字段和 revision，不创建调研任务。
- **展示草稿**：open 接收 draftRef，在对应表单显示；用户修改后递增 revision。
- **提交**：UI 或 Chat 走同一提交动作；提交绑定 draftRef/revision。若用户已修改，旧 revision 拒绝执行并返回需重新读取/确认，避免覆盖人工修改。

普通业务调用默认不跳页面。包可自愿在动作的非变更性 `presentOperation(input)` 预览、结果信封和任务快照中声明 `{ text, linkLabel?, target?, autoOpen? }` 用户呈现；`text` 最多 1000 字符，`linkLabel` 最多 80 字符，目标仅限本包声明的 ViewRef/DraftRef。缺失或非法的可选呈现不影响业务调用，也不取代必需的安全确认 `presentInput`。宿主仅对当前会话中新发起的操作按声明尝试自动打开，先经包的目标解析与原有未保存输入保护；用户手动导航后不再拉回，任务进度及重载历史不重复打开。打开失败不改变业务状态。无呈现时仍可用明确的手动打开工具；不将当前屏幕自动视为 Chat 的全部上下文，必要的主题/公司 ID 来自显式对象引用或查询结果。

UI 对导航返回 opened、blocked（例如未保存编辑）、unsupported 或 not_found。blocked 时提供“打开”入口，不丢弃用户草稿；模型不能把请求发出当作已经打开。页面渲染失败与业务任务成败分开报告。无 UI 包不声明 view，仍可执行动作和读取结果。

## 9. 任务协议、幂等与生命周期

taskRef 由 capabilityId 与不透明 taskId 构成；公司调研将其适配到现有队列条目/报告，不再建立第二套执行队列。任务查询至少返回：

- queued / running / paused / succeeded / failed / cancelled / interrupted；
- 可选阶段、进度、可否取消、创建/更新时间；
- artifactRefs、warnings 和安全错误。

公司调研的一轮成功、二轮失败应返回 failed 并明确失败阶段，同时保留可读取的原始报告引用，不谎报全部成功。取消是否保留产物由动作说明约定；沿用当前规则，用户取消当前调研删除该次未完成记录，不影响已有报告。

现有队列终态会清理，因此包必须保存最小任务回执（taskId、invocationId、状态、产物引用），不能把当前队列当作唯一查询来源。成功结果引用业务报告；已删除、已清理与从未存在要返回可区分状态，不能导致自动重跑。

相同 invocationId 的传输重试返回同一任务/结果。调研入队和回执须在同一原子持久化边界内完成，或以先落盘的调用标识恢复关联；若提交结果不确定，只允许查询核对，禁止自动再次付费执行。模型主动重复调用产生新 invocationId，仍由现有“同公司不可同时入队”等业务规则约束，不声称解决所有重复意图。

首版回执按终态完成时间保留 30 天，活动任务不清理；清理不删除报告。宿主签发的调用标识带可验证有效期，过期写重试明确拒绝而非新建；用户确认重新执行是新调用。此保留规则不代表长期审计平台。

退出应用后依照包当前恢复规则标记暂停/中断，不自动续跑付费任务。重开后 Chat 从持久 taskRef 查询。切换对话、关闭能力页面不取消任务；取消 Chat 当轮工具请求也不自动取消已接收的后台任务。

Chat 保存任务与原会话的关联。完成通知按事件 ID 去重，先展示任务卡状态；不在另一轮生成过程中强插消息或无限自动轮询。用户原请求包含“完成后分析”时，空闲后可调度一次后续分析；有新的用户输入时优先处理新输入。单纯“开始调研”不自动产生额外 LLM 分析消耗。

## 10. 产物读取与分析依据

artifactRef 包含 capabilityId、artifactId 与 revision。返回元数据包括类型、标题、创建时间、内容状态、质量提示和可用读取方式。引用不是任意磁盘路径，所有读取重新经过包可用性与对象访问校验。

产物内容可为文本、结构化 JSON、表格行、记录集合或受控文件引用；公共读取信封声明 format、revision、分页/截断信息，不强制摘要、章节或网页引用。证据引用可以定位工单、内部记录、文件或网页，由包给出可解析的引用；网页来源与事实映射是公司调研适配，不是每个包的必填字段。不支持模型直接读取的二进制返回类型、摘要或受控打开方式，不把大段二进制填进模型上下文。

公司报告默认提供：摘要/章节目录、指定章节正文、来源清单及事实到来源的引用。原始/结构化两类内容明确区分，保留截止日期、生成时间、联网证据状态与阶段失败信息，供 Chat 判断是否可分析。

小结果直接返回；长结果分页或按章节读取，每次明确截断状态、下一游标和 revision。宿主有统一响应大小上限，包声明更低值不能突破上限；不得静默截断却声称已读完整。

已有重试会更新同一报告记录，因此 runId 本身不足以保证内容固定。首次读取取得内容 revision，后续读取携带 revision；内容变化返回 revision_changed，模型重新获取，不拼接不同修订版。不为此强制保存所有历史内容副本。

Chat 分析保留“来自哪个报告、哪个修订版、哪些来源”的引用。旧工具结果可以留在会话中作为历史依据，但必须与当前查询结果区分。禁用/移除包后，已读文本可阅读，不能继续读取新内容或执行旧动作；删除产物返回 not_found，不自动重建。

## 11. 更新与兼容

包版本遵循语义化版本：新增兼容操作提高次版本；删除、改名或不兼容参数变更提高主版本；修复与说明更新提高补丁版本。构建摘要覆盖动作契约和说明，即使作者漏改版本，也不能错误复用旧说明。

本设计新增动作影响、页面/任务/产物协议，以 manifest protocolVersion 2、hostApiVersion 2 落地。新宿主继续加载现有 v1 包用于原 UI；v1 不自动获得新 Chat 动作通路。公司调研在本批升级到 v2。旧宿主拒绝 v2 并给出需升级提示，不尝试忽略未知字段。

加载时校验声明与实际注册的一致性；新增 action 可发现，删除 action 不再可调用。旧会话请求过时操作返回 contract_changed/action_unavailable 并刷新说明，不把它自动替换为语义不明的新动作。

开发者无需维护针对某个模型的专属提示词。目录/说明是唯一公开使用契约；调整 UI 不改业务接口时，Chat 不受影响。

## 12. 包作者交付规则

一个可用包必须包含兼容清单、预构建入口、操作说明及所需资源；UI 可选，任务/产物/view 适配只在声明支持时必需。依赖须自带或使用宿主允许的 SDK，不要求安装后运行 npm 或编译 TS。

安装位置是应用数据目录的 `capabilities/<包目录>/`，不是开发仓库源码目录。退出应用后放入，启动发现，新包默认关闭；用户启用并重启后加载。已启用包的合法更新重启生效。缺依赖、协议不兼容、重复 ID、路径越界均明确拒绝，其他包和 Chat 仍正常。

包通过明确宿主服务使用 LLM/Search/Usage，不获取全部配置或密钥。遵守接口是工程兼容保证，不是防恶意代码保证；首版不自动运行未知来源包，不承诺未经审阅第三方包安全。

后续交付 `capability.开发指南.md` 与最小可运行模板：创建包 → 声明操作 → 实现共享业务 → 可选页面 → 长任务/产物 → 构建 → 安装 → 验收。指南必须对应实际 SDK，本草案不充当已实现教程。

## 13. 首个闭环与必要验收

首个公司调研动作集仅覆盖：查询主题/公司/报告、准备调研草稿、提交单公司调研。任务查询/取消、报告读取和页面打开走公共协议。其他导入、批量、删除、Word 导出动作不自动向 Chat 开放，后续逐项登记；现有 UI 功能不删除。

贯通场景：用户指定已有主题与公司 → Chat 查询 ID → 按需读取说明 → 准备草稿并确认 → 进入原调研队列 → 显示进度 → 获取指定报告修订版 → 分析并提供查看入口。

只做必要契约与行为验证：

1. 零包、禁用包、修改勾选未重启：目录与实际可调用动作一致。
2. 一个不含公司逻辑的最小模板包可接入，证明宿主未写死 A。
3. UI 与 Chat 的同参数请求落同一业务服务；参数错误、缺 Key、确认未完成不启动付费任务。
4. 重复传输不重复入队；结果不确定时可查询；同公司并发遵循现有约束。
5. 队列清理、重启、取消及二轮失败后任务/产物状态真实，已有报告不丢失。
6. 导航不隐式提交；人工修改草稿后旧 revision 无法覆盖；后台完成不抢页面。
7. 新增/删除动作或修改文档后，重启刷新目录，旧说明失效；历史记录仍可阅读。
8. 长报告分页有引用、修订校验与截断标识；关键边界定向验证后交用户手测，不铺设大规模新测试平台。
