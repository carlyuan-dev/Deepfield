# Capability 架构设计文档

日期：2026-09-20  
状态：架构已批准；第一批基础机制已实现，尚未接入生产启动。真实 Capability A 拆包、管理界面与 Chat 调用仍待后续批次。
首个落点：Capability A，公司研究，稳定 ID 为 `company-research`。

## 1. 目标与范围

一个 Capability 是一个自包含的业务包。应用启动扫描包清单，只加载用户已启用的包。包可有多个页面、阶段和动作，但通过统一协议被界面与 Chat 调用，不需要为每个新能力改写 Chat。

硬性要求：Capability 是完全可选的扩展。移除任意包、全部包或整个扫描目录后，主 Agent、Chat、LLM/Search 设置、通用工具与 Usage 仍能正常启动和运行。无包是正常状态，不是故障；宿主不能要求某个具体包存在，也不能通过公共总入口、Worker 初始化或存储初始化间接导入它。

本文描述目标架构，具体落地状态以实施计划为准。首版只接纳自己编写、审核并发布的可信包；管理界面改变下次启动配置，不做运行时热插拔。禁用不是隐藏页面，也不是删除数据。

第一批已提供 `packages/capability-sdk/` 清单协议与资源回收容器、宿主侧无执行扫描/不可变选择快照/失败隔离装配协调器，以及独立 main/worker/ui 构建探针。探针 UI 是纯 DOM，不代表真实 React 包加载已经验证；依赖检查使用真实宿主源码入口的独立 Vite 构建，不代表生产配置已完成包化。现有生产入口尚未调用这些模块，**当前仍不能删除真实 Capability A 代码**。验收记录见[第一批实施计划](../superpowers/plans/2026-09-20-capability-packages-phase-1.md)。

不包含：插件市场、任意第三方代码沙箱、在线安装更新、Capability 相互依赖、全量 Base 迁移、通用长任务调度平台。

## 2. 当前事实与拆包障碍

- `apps/desktop/src/main/application-runtime.ts` 同时创建 Chat、研究主题、调研、批量队列与资料补全；创建后会清理中断调研并启动补全。
- `apps/desktop/src/main/index.ts` 固定接线研究 IPC、导出及退出清理。
- `apps/desktop/src/worker/assembly.ts` 静态导入并装配公司调研和公司资料 Agent。
- `packages/application/src/index.ts`、contracts 与 persistence 总入口混合导出业务和公共内容，禁用时可能仍间接加载业务实现。
- `apps/desktop/src/renderer/features/industry-research/` 已聚合大部分页面，应用服务和 Worker 专属代码也已分目录，但没有包注册协议。
- 当前 Base 只有 Usage。通用 Agent 仍在 Worker，已具备独立执行契约和注入边界，尚不是 Base.Agent。

所以当前是职责模块化，不是可选启动模块。迁移必须同时处理主进程、Worker、界面及静态转导出，而非只添加一个开关。

## 3. 包边界与目录

源码目标示意：

```text
capabilities/company-research/
  capability.json          非执行清单
  contracts/               业务输入输出、Schema、事件
  application/             主题、公司、调研、批量队列和 Harness
  runtime/                 专属 Agent 适配、提示词、诊断
  ui/                      多页面、组件、包内路由
  export/                  Word 内容与报告排版
  docs/actions/            模型按需读取的操作说明
  assets/                  模板等资源

packages/capability-sdk/   轻量公共协议、校验规则与宿主接口类型
apps/desktop/src/          扫描装配、IPC、平台实现和公共界面壳
packages/base/             已独立的业务无关基础能力
```

SDK 是公共接口包，不新增职责层级；宿主装配仍是现有应用实施细节。包不导入 Electron 主进程、Chat 内部代码或另一个 Capability 内部代码。

一个交付包包含清单、已构建的 `dist/main.js`、`dist/worker.js`、可选 `dist/ui.js`、说明与资源；不是运行时编译任意 TypeScript 源码。实现时须建立独立构建边界，验证关闭包后业务代码没有被合入宿主启动 bundle。

前端入口采用宿主支持的 UI SDK，React 等宿主依赖不各包重复装载。包静态资源由宿主受控资源路径提供；只解析包内规范化路径，不允许路径越界和任意外部脚本。具体构建格式与加载技术在实施计划中验证，不将一个 `import()` 当作完整解决方案。

## 4. 清单协议 v1

清单是 JSON 数据，扫描它不执行任何包代码。需要声明：

| 字段 | 约定 |
| --- | --- |
| `id` | 稳定、唯一、不可随展示名修改的包 ID |
| `name`、`description` | 用户名称与简短用途 |
| `version` | 包版本，语义化版本号 |
| `protocolVersion` | 首版整数 1；不支持则拒绝加载 |
| `hostApiVersion` | 首版精确匹配宿主 API 主版本，不承诺跨版本兼容 |
| `entries` | main、worker、可选 ui 的包内相对路径 |
| `navigation` | 可选导航标题、排序、包内初始路由；无 UI 的包可只服务 Chat |
| `requirements` | 必需的宿主能力接口；缺少则拒绝激活 |
| `actions` | 可执行操作声明；页面和内部阶段不是动作 |

动作声明包含：稳定动作 ID、一句话用途、`inputSchema`、`outputSchema`、执行模式 `immediate/task`、操作说明路径及文档版本、所需权限、是否要求确认。

首版 Schema 使用限定的 JSON Schema 对象/数组/基础类型及必填、枚举、长度等规则，不接受远程 `$ref` 或执行式校验。复杂业务合法性由包内 Harness 检查。声明必须与实际导出的动作一一对应，未知动作不可调用。

元数据和完整 Schema 可由宿主读取，但默认只把精简目录提供给模型；不因扫描而把所有说明注入上下文。

## 5. 发现与加载生命周期

唯一运行时扫描根为应用数据目录下 `capabilities/`，不修改已签名 app 内容来添加或移除包。安装资源中可以携带 Capability A 的初始安装副本，但它不是第二个扫描来源；首次安装或旧版迁移时复制到扫描根并默认启用。安装初始化标记存于扫描根之外，用户删除包或整个目录后，普通启动和应用升级不得自动重新安装或从内置副本回退加载。重新安装必须是明确操作。首版不做网络下载；人工新加的未知包默认关闭。

启动顺序：

1. 扫描指定目录，只读清单，校验 ID、协议、路径和兼容性。目录不存在或为空返回空集合，不报错；权限拒绝等真实读取故障不能伪装为空，可在管理页提示，但不阻断主 Agent。重复 ID 不静默覆盖；该 ID 标为冲突，不激活。
2. 读取启用配置，生成不可变的本次启动快照，包括包 ID、版本、解析路径、动作与权限声明。
3. 仅对启用且有效的包加载入口、创建实例、注册业务路由与 Worker 处理器。通用 IPC 分发器可常驻，禁用包不能有业务处理器。
4. 完成 main/worker 初始化后发布 ready 状态，才显示导航和开放动作。失败撤销已注册内容、释放资源，不阻断 Chat 和其他包。
5. 启用包根据自身规则恢复持久任务；Capability A 的中断批次维持现有暂停/重试语义，不自动重复付费调研。
6. 退出时停止接收新动作，按现有业务规则取消或保存运行状态，再解除订阅和释放资源。重启不伪装为用户主动取消，不能借此删除已有报告。

已发现包的状态至少区分：disabled、loading、ready、incompatible、failed。管理页分别显示“本次实际状态”和“下次启动配置”，失败包可查看安全错误，不展示 Key 或原始响应。不存在的包不生成 missing 故障条目；其遗留启用配置不参与本次装配，也不构成待勾选项。零包时管理页可以显示普通空态，不弹出错误。

禁用时不导入业务入口、不实例化、不注册动作、不启动补全和队列、不加载页面。静态清单读取、公共数据库初始化不算业务加载。磁盘仍可保留构建产物。

删除文件夹后，下次启动不再注册该包，不能执行旧动作。禁用和移除包均保留数据；清除数据是独立、需确认的操作，首版不提供自动卸载清理。只有用户主动打开已移除包的历史产物或尝试旧动作时，才给出“对应能力未安装”的局部提示，不影响历史对话阅读或其他功能。运行期间直接删除文件不属于热卸载承诺；若影响当前任务，应使该任务安全失败，不拖垮宿主。

## 6. 执行协议

界面和 Chat 使用同一动作服务，不分别实现调研业务。内部组件调用可以保留类型化方法，但所有对外动作经过统一校验与生命周期入口。

执行请求包含：`capabilityId`、`actionId`、`input`、宿主生成的 `invocationId` 和来源上下文。来源、权限、确认凭据由宿主可信通道提供，不能让模型在参数中自报“已授权”。

统一返回：

- immediate：校验后的业务结果或安全错误。
- task：快速返回 `taskId` 和状态，由包适配其原有任务或批次 ID，不额外复制一套业务状态机。

任务查询提供 queued/running/succeeded/failed/cancelled/interrupted/paused 的公共状态、可选阶段/进度、产物引用和安全错误。具体业务状态由包映射，不要求修改现有数据库枚举。事件带 taskId、顺序标识和类型；查询快照为恢复依据，事件只是增量通知，不假设不会丢失。

宿主提供统一查询、取消、打开产物和完成通知转发。长任务不能占住一次 LLM 请求等待整份报告；Chat 存储任务关联，后续查询或完成通知沿现有会话执行机制处理，不并发插入正在生成的一轮。

相同 `invocationId` 的传输重试不得重复创建任务；重复用户意图是否需要重新执行由上层确认和业务规则决定，不对相似文本自动去重。

参数与返回值均校验；协议不合法应报告协议错误，不能归类成 Search 失败。沿用现有 AppError 体系，新增错误类别只补缺失部分。公开错误含安全 code/message/retryable，原始异常仅进入脱敏诊断。

## 7. Chat 渐进发现与说明复用

三个步骤：精简目录 → 按需加载操作说明 → 调用操作。

这三个步骤属于宿主/Chat 的可选工具接入，不属于通用 Agent 执行器内置业务。执行器只接收工具和上下文，不扫描文件夹、不识别 Capability A、不假设有 Capability。若本轮没有可调用 Capability，不注入功能目录、操作说明或 Capability 专用 describe/invoke/任务工具；普通搜索和其他已授权工具照常使用。历史中出现过的 Capability 调用记录可以保留，但不能因此恢复工具或声明该能力仍可用。

- 每轮提供本次启动 ready 且允许 Chat 使用的包和动作：ID、用途、说明是否已加载。不给全部参数 Schema 和使用手册。
- `capability_describe` 工具按包/动作读取说明及 Schema；宿主缓存已校验结果，并把该动作加入本会话可用集合。
- `capability_invoke` 是统一调用入口，外层携带包 ID、动作 ID 与参数；内部参数按清单 Schema 再校验。协议 v1 不依赖模型供应商支持嵌套动态工具注册。
- 通用任务查询/取消通过公共入口访问，不为每个 Capability 重复增加一套工具。

说明由包提供，不得覆盖宿主系统指令、权限或确认要求。加载说明不会自动授予执行权，调用时重新检查启用、就绪、权限、版本和输入。

“读过一次”由 Chat 管理，以会话 ID、Capability ID、动作 ID、包版本、文档版本/内容摘要为键。重复读取不重复追加完整说明；历史压缩后不能仅凭已读标记假定模型仍看得到，Chat 按当前相关操作恢复必要说明和 Schema。

初版不做语义文档搜索或自动多级手册检索。不同会话隔离，重启后只复用与当前包版本一致的记录。卸载或禁用后历史内容可阅读，但执行被拒绝。文档复用减少重复内容，不承诺输入 Token 免费；有效上下文内文本仍按实际服务规则计量。

## 8. Base 与宿主接口边界

Capability 需要的通用能力优先使用 Base 公开接口，没有的业务能力写在包内。潜在公共能力先证明复用价值再抽取，不要求拆 A 之前迁完 Base。

首版宿主向包注入有限接口：通用 Agent 执行、模型和工具访问、配置解析、Usage 来源绑定、存储事务/仓储适配、任务事件、产物保存与打开、日志及时钟。当前实现仍可位于 Worker、retrieval、tool-platform；由宿主适配，不能宣称这些已经成为 Base 模块。

后续通用存储可抽为 Base.Storage，提供连接、事务、参数化查询、数据空间和迁移执行机制。业务表定义、仓储、迁移脚本和保留规则归各模块；Base 不认识公司、报告或对话。本轮仅形成窄存储接口，不实施 Base.Storage 迁移。

包不拿到整个 ApplicationRuntime、全仓储对象、任意 IPC 或密钥集合。模型/搜索走统一计量路径，宿主绑定 capability/action/task 等来源标识。通用 Agent 继续优先复用 Pi，不在 Capability SDK 另写 Loop。

权限取宿主许可与动作声明的交集；阶段 Harness 可以继续缩小工具集合，不能扩大授权。没有自己的 UI 不影响 Chat 调用，有 UI 也不能绕过参数和权限校验。删除、覆盖、导出选址等动作需要宿主可信确认或文件对话框；不是模型声称用户同意即可执行。

这是可信代码的工程约束，不是恶意代码的安全沙箱。第三方包若未来开放，需另行设计进程隔离、安装验证和权限强制措施。

## 9. Capability A 拆分映射

| 当前内容 | 目标归属 |
| --- | --- |
| application/capabilities/company-research | 包内 application；包含主题、公司补全、调研与批量服务 |
| worker/capabilities/company-research | 包内 runtime；保留专属提示词、校验、诊断 |
| renderer/features/industry-research | 包内 ui；公共 Modal/Markdown/链接复制组件改走宿主 UI SDK |
| main/company-research-word-export 中的报告转换/排版 | 包内 export；Electron 保存对话框与文件写入留宿主 |
| 公司识别/资料补全的专属适配 | 包内；通用模型网关、配置与用量留公共实现 |
| research/company 业务 Schema | 包内 contracts；公开结果经 SDK 通用信封传输 |
| 主进程、Worker 的具体业务注册 | 改为包入口装配，不在宿主列举研究服务 |
| Chat、LLM/Search 设置、Usage、通用工具平台 | 留宿主/公共包，不跟随 A 启停 |

首版数据兼容取舍：沿用现有 SQLite 表、ID、外键和迁移链，不迁数据库文件，不重建已有报告。现有公司相关 repository/migration 暂留 persistence，由启用后的包经窄适配使用；这是明确保留的遗留耦合，不声称首次拆包已完全拥有独立存储。

上述过渡只允许宿主保留自足的旧表迁移和数据访问代码，不允许这些代码反向引用包内文件。无包启动不得创建公司业务服务或运行其恢复逻辑；遗留迁移和公共数据库初始化必须在完全没有 Capability 目录时也能完成。新包迁移仅在该包启用后运行，未安装包不能成为主库启动的必需迁移依赖。

新包使用按 Capability ID 划分的数据空间与自身版本化迁移，不访问其他包表。A 的公司跨研究主题唯一身份规则不变；其他 Capability 未来若需要共享公司目录，另行设计公共实体服务，不直接共享 A 内部表。

Cap A 对外动作分组：主题/公司列表读取、导入与补全、单公司调研、批量调研、任务查询/取消、报告读取/重试/导出。只有实际实现并校验的动作才进入清单；“允许未来声明”不等于首轮把所有界面按钮暴露给模型。Chat 首个贯通目标是选择既有公司→发起单公司调研→查看进度→读取报告，其余按同一协议增量登记。

## 10. 迁移顺序与验收

设计批准后的实施顺序：

1. 确定最小 SDK、清单与包构建格式，用无业务探针验证 main/worker/ui 可以真正按需加载。
2. 抽离 A 的装配与数据端口，保留行为；迁移代码进包，消除启动路径和公共总入口的静态业务依赖。
3. 增加能力管理与启动快照，启用/禁用均验证后台是否实际创建；不只看导航。
4. 接入 Chat 目录、说明复用和最小调用闭环；复用现有 Pi 工具执行机制。
5. 必要离线验证、打包后交用户手测，按 develop→staging→main 推进。

最低验收：

- 在隔离测试目录分别移除 A、移除全部包、移除整个扫描根，主 Agent/Chat/设置/通用工具/Usage 均正常，扫描为空且无缺包报错；不触碰用户真实包或数据。
- 携带旧启用配置、历史工具记录和报告引用启动时，缺包不会导致导入异常、恢复队列或重新安装；只有主动访问旧能力产物时提示不可用。
- 零可调用包时，实际模型请求中没有新注入的 Capability 目录、说明和专属工具；执行器不要求 Capability 注册表存在。历史文本不作为当前可用性依据。
- 关闭 A 后入口模块初始化探针为零，主进程/Worker 都无 A 实例、队列、订阅及动作处理器，Chat/Settings/Usage 正常。
- 绕过界面直接调用禁用或未知动作仍被拒绝；历史说明不能恢复权限。
- 开启 A 后原有公司、报告与失败重试记录可用，两轮/批量/取消/导出行为不变。
- 加载不兼容、损坏、重名包时明确标错，其他功能启动不被拖垮；部分初始化可释放。
- 说明重复加载不重复注入；上下文裁剪后可恢复；升级后旧版本失效。
- Chat 调用与界面调用落到同一业务服务；长任务可追踪，重复请求不重复付费执行。
- 构建产物验证禁用包未被静态装入主 bundle；操作说明或报告不能越界访问包外文件。

只做这些关键边界与现有行为的必要测试，不为首版建立庞大的插件测试平台。当前 macOS Seatbelt 下不启动 Electron 自动测试；桌面运行由用户手测。
