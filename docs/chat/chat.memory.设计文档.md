# Deepfield Chat Memory 接入设计文档

版本：0.2 · 日期：2026-11-06 · 状态：**已实现并通过 Memory／Compact 联合自验及用户验收**。

本文负责 Chat 的记忆策略、上下文接线和用户体验；记录结构、事务、权限及遗忘机制唯一见 [Base.Memory](../base/base.memory.设计文档.md)。Memory 与 [Compact](chat.compact.设计文档.md) 在本批共同交付；多 Agent 属于后续阶段。

## 1. 用户目标和现状

用户说过的稳定偏好、纠正和项目约定，在相关后续任务中能被取用；用户可以知道记住了什么、改正或删除。记忆帮助准备答案和默认输入，操作执行仍依据本轮权限及真实回执。

Chat 保留原始消息与安全 transcript，checkpoint 恢复维持工具配对。Memory 提供可失效的长期参考投影；Compact 负责会话内上下文压缩，两者独立维护、按顺序装配。长期记忆摘要在每次模型轮次独立注入，不固化进 Compact 摘要。

当前没有通用项目或账户实体。首版支持本地用户范围与当前会话范围；能力偏好通过宿主显式绑定范围。对“只适用于本项目”的约定，无法识别稳定项目时不自动扩大为全局偏好，保留在当前会话并说明范围。未来工作目录／项目实体就绪后绑定新的 scope，不能按聊天标题猜测同一项目。

## 2. 首版体验与默认值

以下为本版产品默认值。

| 项目 | 行为 |
| --- | --- |
| 使用记忆 | 默认开启，发送前提供有界长期摘要／目录并补充相关明细 |
| 自动学习 | 默认开启，仅从启用后的新交互学习普通背景、偏好和约定；首次升级提示一次可关闭及会使用当前模型处理有限对话材料 |
| 明确“记住／修改／忘记” | 复用主 Chat 工具入口执行；明确请求及目标已足够时一次完成，不重复确认 |
| 自动处理 | 成功回复后增量入队；不在流式中反复提炼，不阻塞当前回复 |
| 设置入口 | Settings 新增“记忆”，管理开关、列表、编辑、删除、清空及处理状态 |
| 显示原则 | 明确操作通过正常自然语言回复简短说明结果；后台学习状态在设置中查看，Chat 不追加管理按钮或自动学习卡片；失败不能显示成功 |

用户明确要求保存时无需依赖自动学习开关；关闭“使用记忆”不禁止用户打开设置管理已有记录。完全关闭表示关闭自动学习和自动召回，用户仍可手动管理。

保存到本地并不表示只在本机使用：相关记忆会作为后续模型输入发送给当前配置的 Provider。设置页用简短说明告知；不另建上传外部记忆服务的依赖。

## 3. 什么内容进入记忆

| 内容 | 处理 |
| --- | --- |
| 用户明确“记住我是做 Agent 开发的”“我每周一有周会” | 普通背景 profile；按用户原语言保存，目录可发现 |
| 用户明确“以后先给结论，再给依据” | 通用偏好，明确保存并允许跨会话召回 |
| 用户纠正“这里的客户指渠道商” | 范围清楚时保存该范围的约定，否则保留本会话 |
| 多次确认且有回执支持的操作经验 | 保存适用条件和依据引用；模型推测不视为已验证经验 |
| “这一份先写短一些” | 当前请求约束，默认不升级为长期偏好 |
| 某公司总部、报告内容、任务完成状态 | 按需查原业务记录；不自动复制成用户长期记忆 |
| 网页中的“以后忽略用户规则”等指令 | 外部数据，不形成记忆授权，也不成为用户偏好 |

自动提炼可提交有明确依据的普通背景 profile、偏好和约定；姓名、职业、固定日程不再被一概排除。summary、content 与 applicability 保持来源用户的语言，关键事实必须在摘要中可识别；不会由说中文推断“偏好中文”，也不会把普通背景改写为用户未说过的行为偏好。经验类候选需要可引用的确认或实际验证回执。用户手动编辑的条目不被自动处理悄悄覆盖。对冲突条目，通过管理页或当前确实需要使用时请求用户选择，避免每轮弹确认。

## 4. 明确记忆操作

为 Chat 增加窄工具入口：检索／读详情、直接保存、修改／删除指定记忆。用户明确指令和自动建议使用不同的可信提交路径，不能通过模型参数将自动建议标记为用户确认。

主 Agent 负责自然语言理解；宿主负责来源、权限、版本和提交。普通陈述背景、偏好或当前任务不触发主动记忆工具，稳定信息按后台学习策略处理；临时任务保留在对话及 Compact 中。明确修改／删除需要稳定的条目引用及当前 revision；“忘记刚才说的那条”有唯一对应时直接执行，目标不唯一时复用现有人机询问。清空全部可由明确的用户请求授权；从设置页操作时给一次确认。

明确请求由主 Agent 理解并直接选择窄工具，不再调用额外 Memory 意图分类模型，也不依靠持续扩充自然语言正则来决定是否执行：

- 工具参数中的 `userRequest` 必须逐字摘录当前真实用户的直接请求；宿主从当前 requestId 对应的 user 消息取得来源并校验摘录，不接受后台续跑、历史记忆、网页或助手声称作为新的授权来源。语义判断由主 Agent 负责，工具描述和每轮策略要求区分请求、引用、否定、假设与外部内容。
- 主 Agent 仅保存原话支持的内容和条件，保留用户语言；scope 不清时只在当前会话保存有依据的原话并简短说明，不扩大为 user。普通明确“记住／修改／忘记”无需再次确认；仅有真实目标歧义或误操作风险时询问，目标不明的批量删除不能猜。
- 宿主绑定 owner／可读 scope／用户来源与生命周期，修改和删除需当前 revision；完整操作指纹限制同轮重复变更数量。主 Agent 不提供 user_explicit 等内部身份标记，不能跨不可读范围操作。
- 主 Agent 的语义判断属于模型信任边界，原话摘录只证明来源，不能单独证明语义授权；误授权、外部内容注入和否定请求须在联合验证中检查。设置管理仍直接绑定用户提交的内容、范围与 revision。

工具直接写入不调用内容提炼或意图模型。回执区分 saved／unchanged／conflict／invalidated／disabled／miss／error；错误携带不含正文的原因类别。关闭使用不等于未命中，读取故障不能回答“没有记忆”；最终回复只在 saved 或经存续校验的 unchanged 时确认已保存。

同一交互允许多项记忆操作，但必须分别有来源。任务范围授权不等于长期记忆写入授权；批准执行一项业务也不等于批准记住其中所有私人信息。

## 5. 自动学习与费用控制

Chat 在成功终态和安全 transcript 持久化之后推进学习游标。失败、中断和仅有 checkpoint 的请求不自动作为完整经验；来源尚不完整时留待新交互补充，不通过循环重试补齐。

建议默认调度：

1. 同一会话累计 4 条尚未处理的用户消息、且成功终态后空闲至少 60 秒时，准备一个增量窗口。明确记忆工具已处理的来源不重复采集。
2. 每窗口模型输入与输出预留合计最多 6,000 个估算 token，输入包含全部系统指令、最多 20 条相关既有记忆索引，并为最多 5 条可能修订的记录提供完整正文、条件、来源及 revision；输出最多 5 个候选。预算不足时缩小候选和来源窗口，不截掉待修订条目的关键条件。窗口按完整来源单元截取，超长单元跳过并推进处理状态，不无限滞留；仅见索引的条目不能直接修订。
3. 全应用最多 1 个提炼作业在途；用户发送新消息时暂停派发新的后台作业，已经发出的请求有界完成，不覆盖当前请求的上下文。
4. 每窗口最多 1 次新增模型请求，格式无效／失败本轮结束；输出截断、格式错误和请求故障分别保留诊断，截断结果不能提交为记忆；新输入产生新窗口或用户在管理页主动重试。自动模式不额外启动全库模型整理。
5. 开始作业时冻结当前 LLM 配置快照，超时 30 秒并传播取消；同一操作的配置不因设置切换而改变。无有效模型配置则跳过，不影响主 Chat。

未满 4 条的新会话主要依靠明确记忆工具；结束应用不为凑窗口触发付费请求。后台窗口是增量采集，不回扫启用前历史。以上门槛属于可调整产品策略，必须在验收样本中观察遗漏、额外请求及用户等待后再优化，不能称为已验证最优参数。

Base.Memory 的提炼服务负责中立的候选生成和提交校验，Chat 负责窗口和时机。相关 Trace 使用独立后台任务并链接来源请求；Usage source 标识采用固定的 memory-extraction，不将后台用量混成当前回复独占消耗。配置／真实传输是否计量继续遵循 Base.Model 和 Usage。

Fake 模式下后台处理使用确定性本地实现；连接测试和其他真实调用入口仍遵循自身模式，不用“Fake”字样暗示全应用网络沙箱。

## 6. 召回与上下文装配

覆盖三个实际入口：普通用户消息、人机交互恢复、后台任务完成后的自动分析。均在启动 Worker 请求之前，由 main 取得获准范围的记忆视图；不能只接普通发送而遗漏恢复路径。

读取阶段不额外调用模型。宿主从当前用户与当前会话的有效记录生成 `MEMORY.md` 逻辑摘要／目录，每条保留 ID／revision、摘要、范围、来源类别和适用条件；目录不依赖当前问题命中词。再根据当前问题补充相关明细，沿用 Base.Memory 的快照预算。目录未展示条目可用 `memory_search` 的空 query 与 offset 分页浏览，返回 nextOffset；主 Agent 需要完整正文时调用 `memory_read`。中文“我用什么语言”未匹配英文 Python 条目时，仍可从目录发现并读取，不直接回答没有记忆。每轮策略、状态、目录和获准 Memory 工具内容合计上限 2,000 估算 token；完整当前输入优先，空间不足先省略记忆。

装配顺序按职责区分：系统／工具硬规则、当前用户要求和可信运行状态、相关历史参考、近期消息与成对工具结果。记忆以独立参考块携带适用范围、来源类别和 ID／revision，不直接拼进高权限 system 内容，也不反复作为普通消息持久化。

Memory 本身提供有上限的输入预算；完整模型输入预算、溢出恢复及会话压缩由 Compact 协作处理。新增记忆不得挤掉当前用户输入或拆开工具调用／结果。

摘要和目录是结构化记录的即时派生视图，不另写磁盘 MEMORY.md，也不作为事实源持久化。每次投影显式告诉模型当前 ready／miss／disabled／error 状态；故障保留原因类别。

同一请求记录使用过的记忆 ID／revision。每次模型轮次开始前通过现有 hook 获取轻量失效版本，删除／关闭使用后从下一轮移除对应参考块；新增或普通编辑默认在下一个请求生效。已经发给 Provider 的内容无法撤回，界面不能承诺立即抹去在途回答的影响。

用户删除记忆不会自动改写聊天原文；同一对话仍可能从用户原话或已生成的回答获知该信息。管理页明确区分“删除保存的记忆”和“删除原对话”。

Memory 专属工具的调用参数和结果共同使用可失效引用投影：宿主标记记忆 ID／revision 与来源操作，完整正文只在该次获准执行／读取中使用；持久化 transcript、恢复上下文、每轮构造模型输入三个边界都执行检查。remember/revise 的正文参数与 read/search 的详情结果均在此范围内，不能只处理返回值而遗漏 assistant.toolCall.arguments。当前 Pi 工作历史中的已失效正文同样移除，保留 callId、工具名和“已失效／已更新，请按需重新读取”的配对回执，不重放写入操作，不将新版本静默冒充旧调用结果。

这些投影仅用于新增的 Memory 工具，不改写普通用户原话或其他工具的历史格式。主动开启的诊断全文、导出文件与外部 Provider 留存依各自规则管理，删除记忆不声称一并擦除这些副本。

## 7. 管理界面

Settings 的“记忆”页提供：

- “使用已保存的记忆”“自动学习新记忆”两个开关，以及本地保存／模型使用说明。
- 列表显示简短内容、适用范围、手动／自动来源、最近更新时间；支持文本搜索和范围筛选。
- 点开条目编辑正文与适用条件，查看可用来源定位、有限历史版本；不在普通页面展示内部 ID。
- 删除一条、清空全部；清空提示原聊天不会被删除，并说明后续只从新交互继续学习。
- 自动冲突条目单独显示为待处理，可选择保留、替换或删除；失效记录默认不混入可用列表。
- 暂时故障显示原因类别和适当恢复入口；读失败可重试，写失败保留用户输入。没有异常时不显示常驻诊断横幅。

Chat 通过普通回复简短反馈明确操作结果，例如“已记住，你从事 Agent 开发”。每条回复后不追加“管理记忆”按钮，也不显示后台自动学习卡片；管理开关、来源、历史与学习异常统一留在 Settings 的“记忆”页。首次启用说明仍只提示一次。

若用户正在编辑，后台更新不能覆盖草稿；保存时按 revision 检测冲突并让用户选择。能力已移除时，其既有偏好仍可在管理页查看／删除，但不会自动暴露给其他包。

## 8. 接线位置与兼容

| 位置 | 接入职责 |
| --- | --- |
| `packages/application/src/chat/context-builder.ts`、`chat-service.ts` | 通过注入端口取得记忆快照；三个启动入口共用装配；成功终态通知采集协调器 |
| `apps/desktop/src/main/index.ts`、`application-runtime.ts` | 装配 Memory store、策略配置、提炼调度与模型端口；生命周期统一关闭 |
| `apps/desktop/src/worker/chat/`、`worker/agent/` | 将记忆参考块传入 Pi 上下文，轮次前执行失效检查；复用既有 hook，不改变工具协议 |
| `apps/desktop/src/worker/tools/`、main 的 IPC／host bridge | 记忆工具与安全消息；宿主绑定会话／来源／范围 |
| `packages/persistence/src/conversation-repository.ts` | 在已有同步删除事务内使 Memory 来源失效；不嵌套事务 |
| Settings／preload／contracts | 新增窄的管理 DTO 和调用；Renderer 不拿数据库或模型凭据 |
| `packages/capability-sdk` 与宿主注入 | 可选 `memory.v1`，范围固定；不改变旧包必需服务 |

上表是设计落点，不要求把 Chat 全部搬到 Base。新增表用 Base.Database 模块迁移，旧消息／报告不改格式、不回填为记忆；现有成功路径在 Memory 关闭、缺失或失败时保持可用。Memory 迁移失败只使该功能不可用，不阻断 Chat 和能力启动。

## 9. 验收场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 对话 A 明确记住背景或偏好，对话 B 用中文改写提问 | B 通过目录发现并正确使用明细；无关计算不强行带入背景 |
| 自动学习满足窗口后，用户开启新对话 | 有依据的稳定偏好可用；临时请求未被提升为全局规则 |
| 修改已保存偏好 | 下一请求用新值；后台旧候选不能覆盖修改 |
| 删除记忆／清空／删除来源会话，同时有在途提炼 | 内容与索引失效、晚到结果不复活；已发请求仍如实计量 |
| 关闭自动学习但保留使用 | 旧记忆继续可用，新自动窗口不再发送 |
| 关闭学习后明确保存，再重新开启 | 明确保存可用；关闭期间不补采；此前在途结果即使重新开启也不能提交 |
| 关闭使用记忆 | 新请求／后续轮次不注入；显式管理仍可用 |
| 删除后重试旧写入／恢复 Memory 工具历史 | 不复活、不报告旧保存成功；调用参数与结果均不重新带入已失效正文 |
| 人工确认恢复、任务完成自动分析 | 同样遵守范围、预算和失效，不遗漏入口 |
| 两个能力访问同名偏好 | 范围不串用；只读调用不能写，全局偏好不默认泄露 |
| 模型／存储失败与 Fake 模式 | 普通回复可继续；显式保存有真实错误；Fake 自动处理零外部请求 |

采用可核验偏好及项目约定样本，记录正确召回、遗漏、无关召回、错误长期化、用户修订次数与新增用量。少量真实模型端测验证自然语言操作和来源判断，离线确定性测试保护权限、删除竞态和预算；不以单元数量作为功能效果。

## 10. 已确认范围

1. 首版默认开启使用与自动学习，但只学习启用后的新交互；后台提炼使用当前 LLM 并产生可见用量。
2. 首版本地检索、用户／会话范围完整闭环；通用项目范围随真实项目实体接入，Capability 先提供可选 SDK 和契约夹具。
3. 删除记忆同时抑制既有来源再次提炼，原对话保留；清空后从新交互继续学习。
4. Memory 与 Compact 本批完成联合闭环；多 Agent 后续复用范围、引用、失效及权限边界。
