# Chat Compact 设计文档

版本：0.1 · 日期：2026-11-06 · 状态：已实现并通过 Memory 联合自验及用户验收。

## 目标与职责

长对话和工具循环接近输入预算时，将较早上下文整理为当前会话摘要，继续使用摘要与近期完整消息。用户仍能查看、搜索原始聊天记录。摘要保存目标、约束、决定、完成与失败状态、待办、必要的来源和路径；历史摘要不授予新的执行权限。

Chat 维护时机、会话归属、持久化与恢复。复用 Base.Model、Usage、Trace 及现有 Pi 执行循环；长期用户画像、主题索引和条目由 [Chat Memory](chat.memory.设计文档.md) 管理。对话摘要不是自动学习来源，也不自动成为跨会话记忆。

## 成熟实现与适配

直接复用当前锁定的 Pi Agent Core 0.84.3 提供的 `findCutPoint`、`generateSummaryWithUsage`、`buildSessionContext`、`convertToLlm`。Pi 使用摘要加保留尾部构造上下文，支持递增摘要并保持工具调用与结果成组。参见 [Pi compaction](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/compaction.md)；当前安装版本的会话接口为 `retainedTail`，集成以锁定版本源码为准。

Deepfield 的数据库仍是原始聊天记录的事实源。摘要生成经过 Base.Model，以 `chat-compaction` 归属记录真实用量，Trace 中对应 `chat.compact` 阶段。模型文本仅作为历史参考，不替代当前系统约束、工具权限或宿主操作回执。

## 输入预算与压缩

每次模型轮次前检查输入，包括系统提示、工具定义、消息、模型输出预留和 Memory 预留。采用 Pi 估算与中文保守字符估算的较大值；到可用消息预算的 80% 时开始整理。近期消息按安全切点保留，工具调用及结果不拆开；即使切分当前工具循环，也保留当前用户输入。 已完成的旧轮次若因单条长材料超出近期保留预算，切点向后推进到完整消息或工具批次边界，将旧材料纳入摘要，保留当前用户轮次。

整理先从原始历史执行 Memory 引用投影，不读取注入的长期记忆正文。生成摘要后再进行当轮 Memory 有效性检查与注入，避免长期记忆被复制进不受删除影响的摘要。

超长历史分有界前缀整理；每个前缀和上次摘要必须能进入摘要请求的上下文。每个 Chat 请求最多生成四次摘要，每次无自动重试、60 秒取消信号。摘要为空、输出截断或未有效减少自动压缩输入时不替换旧投影。单条输入或基础工具定义无法装入窗口时明确失败，保留原记录，避免静默丢弃。

## 持久化与恢复

`chat_sessions` 的记录保存可替换的 compaction：摘要、保留尾部、当前请求中已覆盖的原始消息数量、时间和估算前后大小。原始 transcript 仍完整保留。提交摘要时要求原始边界已持久化；恢复从最新有效摘要接续该边界之后的消息。

取消、失败不自动重放工具；成功整理的投影可供后续请求使用，尚未提交的整理不改变历史。删除对话通过现有级联同时删除其摘要。普通编辑和恢复沿用既有会话和交互状态机。

## 用户体验

自动整理复用现有执行活动显示短提示；完成后继续回答。支持在当前对话输入 `/compact` 或 `/compact 整理重点`，整理完成后返回简短结果。无需新增常驻按钮或独立确认框。手动整理与后续真实回答的费用分别计入对应用途。

## 联合验收

- 已保存长期偏好在新对话可用；当前任务摘要仅在本对话生效。
- 长对话超过原来的 40 条消息后仍保留早期目标和已完成事实。
- 工具循环整理后调用与结果成对，已经完成的有副作用操作不因整理而重放。
- 整理后重启或切换会话，仍能根据摘要与原记录继续。
- 修改、删除或关闭长期记忆后，Compact 不恢复独立记忆正文；原对话中的用户原话仍按聊天记录管理。
- 取消和模型失败保留旧上下文；真实摘要请求在 Usage、Trace 中可关联。
