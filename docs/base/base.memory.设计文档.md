# Deepfield Base.Memory 设计文档

版本：0.2 · 日期：2026-11-06 · 状态：**已实现并通过 Memory／Compact 联合自验及用户验收**。

本文是记忆机制的正式设计入口；Chat 的采集、召回和管理体验见 [Chat Memory 接入设计](../chat/chat.memory.设计文档.md)。安全契约、SQLite 适配和有界提炼分别通过独立入口导出，Chat 为首个消费者。

## 1. 目标与方案选择

记忆保存可跨会话复用的普通用户背景、用户偏好、已确认约定和有依据的经验，使 Agent 后续按需取用，并允许用户纠正、删除和关闭。原始对话、业务事实及执行状态仍由各自仓储负责。

采用已讨论的 B 方案：通用记忆生命周期及可选模型处理放在 Base.Memory，Chat 负责使用策略，Capability 只依赖获准的窄接口。

| 方案 | 取舍 |
| --- | --- |
| A：轻量 Base 与 Chat 完整记忆分开 | Chat 初期改动集中，但提炼、检索、更新、失效容易形成两份实现；其他消费者需要完整能力时再抽取 |
| **B：统一 Base.Memory，消费者组合使用** | 统一身份、来源、版本和生命周期；通过分入口、受限句柄和上层策略控制复杂度。当前选择 |

“完整”指保存、提炼、整合、召回、修订、遗忘的机制闭环，不要求每次调用都启动全部流程。直接保存已确认偏好与检索不需要调用模型。

## 3. 职责和依赖

| 归属 | 职责 |
| --- | --- |
| Base.Memory 核心 | 中立记录、受限访问、检索、版本校验、去重、冲突与失效、遗忘、事务和可选提炼契约 |
| Base.Memory 可选处理 | 对调用方提供的有限材料生成候选与修订建议；验证模型输出，提交前重验来源和 revision |
| Chat | 哪些交互可采集、何时处理、当前可读范围、哪些记忆进入模型输入、用户管理与提示 |
| Capability | 业务偏好语义、何时读取／保存、默认值如何使用；业务数据和流程状态留在包内 |
| 宿主 | 本地身份、授权句柄、存储与作业生命周期、IPC、模型快照、删除联动 |

提供 `@deepfield/base/memory` 安全契约、`@deepfield/base/memory/runtime` 通用执行与提炼服务、`@deepfield/base/memory/sqlite` 存储适配。安全入口不加载 Node、模型客户端或凭据。

- SQLite 适配复用 Base.Database；提炼复用 Base.Model；错误复用 Base.Errors。上层注入已解析模型快照和端口，Memory 不读取当前 Profile 或 Chat 仓储。
- Config 管策略配置；Usage 仍在真实模型请求边界记账；Trace 只观测阶段、状态和关联 ID。Memory 不建立第二份用量账本。
- Base 不导入 application、Capability SDK、Electron 或 React。Chat 源消息／Capability 资源在 Base 中都是不透明来源引用。
- Compact、对话历史、业务回执、授权状态保持独立。模型输出及记忆不能授予工具权限，也不能证明操作已执行。

## 4. 身份、范围与权限

### 4.1 首版实际范围

当前桌面没有账户与通用项目实体。宿主为当前 userData 生成稳定的 `localOwnerId`；它表示本地资料域，不是登录身份，不使用 LLM Profile ID 代替。

| 范围 | 绑定方与用途 |
| --- | --- |
| 本地用户范围 | Chat 使用，承载跨会话通用偏好与适用条件明确的经验 |
| 会话范围 | 宿主绑定 conversationId，承载用户限定于该对话的约定；只在该会话召回 |
| 能力范围 | 宿主绑定 capabilityId，承载包的偏好；可再绑定包内资源标识 |

范围在 Base 表示为不可由模型自由扩大的 `ownerId + namespace + scopeKey`。同名标签不等于同一范围。项目／工作目录范围在未来出现真实实体后由宿主新增绑定；本版不把聊天标题、自由文本中的“本项目”或文件路径猜成项目身份。无法确定范围时留在当前会话，必要时向用户澄清。

### 4.2 受限句柄

宿主构造只读或可写句柄，固定允许的范围和方法；所有按 ID 获取、更新、删除也执行相同范围检查。跨范围只返回通用不可访问结果，不泄露条目是否存在。

模型与包不能通过传 ownerId、namespace 或存储路径提升权限。全局用户记忆不会默认暴露给 Capability；确有需要时，由宿主选择用户允许的偏好投影作为显式输入。

当前能力包是可信本地代码，已有 Database scope 不是 SQL 表级沙箱。因此此接口保证宿主正常调用与 SDK 使用时的范围约束，不声称能够隔离恶意同进程包；执行隔离仍属于后续平台权限建设。

## 5. 记忆记录与来源

关键字段如下，持久化 schema 与公共接口分别版本化。

| 字段 | 语义 |
| --- | --- |
| `id / revision` | 宿主生成的稳定标识与递增版本；修订使用 expectedRevision |
| `scope` | 可信句柄固定的范围，不接收模型生成值 |
| `kind` | profile、preference、convention、experience；profile 承载用户明确的姓名、职业、技术背景和固定日程等普通背景；用于展示和策略，不包含业务领域枚举 |
| `summary / content / applicability` | 简短索引、单条可读内容、明确适用条件；一条聚焦一项有来源的事实或约定 |
| `origin` | user_explicit、user_edited、auto_extracted、consumer_confirmed；来源权威由入口确定 |
| `sources[]` | 不透明来源 ID、版本、时间和最小证据定位；不默认复制完整对话或网页 |
| `status` | active、conflicted、superseded、expired；被遗忘内容另按删除协议移除 |
| `createdAt / updatedAt / lastUsedAt / expiresAt?` | 维护和有效性；使用频率不提升事实权威 |
| `supersedes? / dedupKey / generation` | 修订关系、幂等与删除竞态控制；内部字段不直接给模型 |

结构化记录是记忆的唯一事实源。`MEMORY.md` 是逻辑名称，表示从当前有效记录即时生成的长期摘要／目录；不另存一份正文文件。每条摘要携带自身 ID／revision，明细按需读取；编辑、删除、关闭使用和来源失效后，下轮投影重新校验并剔除过期摘要。不会把多条记忆融合成无法按来源失效的无引用文本。应用可以保存本轮使用过的 ID／revision，定位后续问题，但不把整条记忆复制进 Trace 元数据。

源材料分清用户原话、用户确认内容、工具可信回执及外部数据。提炼结果必须引用本次允许的来源；LLM 自评置信度不能代替依据。自动采集包括原话明确、稳定的普通用户背景，以及稳定偏好、明确纠正和已确认约定；summary、content 和 applicability 保持来源用户的语言，技术名词原样保留，不因用户使用中文提问而自行新增中文回复偏好。经验必须同时写适用条件及实际验证依据。

口令、密钥、令牌不写入 Memory。普通业务事实优先保存业务记录引用，而非复制为长期记忆；敏感个人事实不从聊天中自动提炼。用户明确要求保存的私人内容需要说明本地存储及可能随相关模型请求发送的行为。

## 6. 写入、提炼与修订

### 6.1 两条入口

**直接写入**：用户编辑或宿主确认后的有限内容，经格式、长度、范围和来源校验后提交，不额外调用模型。明确“记住／更改这条”的自然语言可由主 Agent 解析，但 user_explicit 身份必须由可信交互路径结合当前用户消息授予，不能信任模型自报。

**候选提炼**：调用方提供来源窗口、相关既有记忆、允许种类和预算；Base.Memory 经 Base.Model 返回有来源的候选／修订建议。提炼不执行工具，不读取任意会话或改变权限，模型只提出有限变更。

提炼使用一次结构化响应；格式或来源校验失败不落库，保留错误类别和关联 ID，无无界修正循环。缺少模型配置时直接写入／读取仍可用，自动提炼跳过并在管理页显示可处理状态。

### 6.2 提交规则

1. 领取作业时捕获 source generation、范围 generation、既有 revision 与模型配置快照；模型调用在数据库事务外完成。
2. 输出限于本次可见记录及来源，拒绝未知 ID、越界范围、缺证据和非法操作。首版每次最多产生 5 项候选变更。
3. 所有提交在事务内重验句柄授权、来源、generation 和 expectedRevision。自动提交另校验来源可采集、自动学习仍开启及 learning epoch 未变化；用户明确写入不受自动学习开关限制。
4. 完成上述有效性校验后，才处理同一操作键或同源同内容的幂等重放。原记录仍存在且与该结果一致才返回 unchanged；已经删除、替换或授权失效则返回失效／冲突，不复活记录，也不把历史成功冒充当前已保存。
5. 提交成功后更新索引并发出变化通知；失败不声称“已记住”。观测失败不回滚已经成功的业务提交。

自动建议不能直接覆盖用户明确写入／修改的记忆。用户明确更新同一条目可替换旧版；来源明确的后续纠正可作为有证据的候选，身份或范围不清时等待用户选择。自动条目与显式条目冲突时隔离自动候选；两个自动条目相互矛盾且无法确定时，两者均停止作为确定约定注入。相同内容补充来源，近似但语义不同的内容保留独立，不能只凭字符串相似度覆盖。

自动修订或来源合并只允许针对本次实际提供完整正文、适用条件、来源及 revision 的条目。仅见索引的条目可以提出待核对关系，不能直接改写正文；下一次核对须读取完整记录并重新校验。

首版所有可撤销修订保留最多 5 个历史版本供用户查看，超过部分丢弃正文。遗忘时所有版本一并删除。active 记忆默认不自动过期；expiresAt 到期后停止召回。自动经验长期未使用可以降低召回排序，但不能据此删除用户确认的约定。

## 7. 检索与模型输入

读取采用始终可见的有界长期摘要／目录，再辅以本地词项检索；词匹配不是唯一入口。`MemoryReader.listIndex` 读取当前可用条目，支持 offset 分页；Chat 按摘要预算投影，不要求增加 Embedding 配置或外部存储服务。候选排序组合标题／内容匹配、适用条件、范围、用户显式程度与更新状态；中文按 Unicode 词段及双字片段建立本地检索索引。具体权重是实现参数，须用中英文改写样本验证。

`search(query, limits)` 先执行范围和状态过滤，再排序；词项排名不冒充语义正确性。首版允许注入可替换检索策略，但不提前实现多套后端。

调用方可先读短摘要目录、再按 ID 取详情。Chat 在发送前为目录预留最多 1,400 个估算 token，并在总共 2,000 token 的快照预算内补充最多 8 条词项命中明细；每次模型轮次进一步将策略、状态、摘要和获准 Memory 工具内容限制在 2,000 估算 token 内。单个快照最多 100 条引用，实际数量由预算决定。未展示条目通过目录 nextOffset 分页读取，关键词未命中不代表没有记忆。系统提示、当前用户输入与本轮工具先有预算；过长条目保留摘要并按需读取完整条件。

没有足够匹配项时可以不返回，不能为了“用上记忆”强行注入。检索零命中、相关记忆遗漏和错误召回都应可验证；关键词召回不足时再依据样本选择语义检索，不能将首版称为已具备向量语义召回。

记忆以标注来源／范围的历史参考区进入模型输入，不升级为 system 指令或执行授权。最新用户明确要求优先；冲突需要核对。调用方负责把真正需要的信息放入本轮上下文，Base.Memory 不修改 Chat 消息列表。

## 8. 遗忘、关闭与来源删除

### 8.1 用户遗忘

“删除记忆”默认表示：删除条目正文、历史版本及索引，同时禁止现有来源再次生成这条记忆。原对话仍存在，删除界面需明确“原对话保留；如需移除原文，请另行删除对话”。

在一笔事务内完成：推进相关 generation，删除正文／派生索引，写入无正文的来源抑制记录；领取与提交作业都检查抑制。首版采用保守的源消息级抑制，可能同时阻止从该消息重新提炼其他记忆，不宣称精确到语义的永久遗忘。新的用户消息明确要求重新记住时可以重新保存；旧后台作业不得复活记录。

抑制记录保存 owner、source ID/version、截止位置和删除序号，不保存被删内容摘要。它跟随仍可被采集的来源保留；来源永久移除且相关作业已失效后可回收。清空全部记忆推进资料域 generation 并记录采集高水位，默认只从清空后的新交互继续学习。高水位使用宿主提供的稳定来源序号／游标，不单靠系统时间判断新旧。

### 8.2 来源删除与并发

Chat 删除会话时，应用在现有业务删除事务中调用 Memory 的同步来源失效入口；不得嵌套 Base.Database transaction。来源删除推进 generation、取消未发作业，并重验已发请求的提交资格。单一来源派生的记忆随之移除；合并记忆失去任一必要来源时先停止召回，不能把部分依据当完整支持。用户编辑成独立记录的记忆以该显式编辑为新来源，可继续保留，删除对话时明示这一边界。

已发给 Provider 的内容无法撤回，取消只尽力终止请求并阻止提交。记忆删除后，宿主清除检索缓存，后续模型轮次不再注入；已有会话文本中的原话仍按历史规则存在。数据删除为应用层逻辑／持久内容删除，不承诺擦除 OS 备份、Provider 历史或 SQLite 已释放页。

### 8.3 开关和故障

使用记忆与自动学习分开配置。关闭自动学习立即推进 learning epoch、拒绝新自动任务并使在途结果失效；已保存记忆继续可读，用户仍可明确保存。重新开启记录新的采集高水位，不补采关闭期间的交互，旧 epoch 作业即使此时开关已开启也不能提交。关闭使用记忆停止后续召回，不隐式删库。关闭全部功能同时关闭这两项。

自动学习／召回失败不阻塞 Chat 主回复，但必须有可定位状态；显式保存／删除失败应告知用户，不能伪装成功。数据库异常时停止 Memory 写入，其他功能按原路径继续。首次启用只处理之后的新交互，不自动扫描历史库。

## 9. 接口与 Capability 接入

接口定义见 `packages/base/src/memory/index.ts`；提炼入口见 `memory/runtime.ts`，SQLite 适配见 `memory/sqlite.ts`。

| 入口 | 方法与语义 |
| --- | --- |
| `MemoryReader` | version、search、get、listIndex；返回授权范围内的安全视图 |
| `MemoryWriter` | remember、revise(expectedRevision)、forget(expectedRevision)；幂等 operationKey，由宿主绑定来源 |
| `MemoryProcessor`（可信端） | propose(sources, existing, policy, signal)、commit(proposal, expectedGeneration)；结果与提交分离 |
| `MemoryMaintenance`（宿主） | invalidateSources、clearScope、health、revoke；具备参与既有同步事务的入口 |

`memory.v1` 是可选 SDK 服务，包通过 has/get 和版本检查获取宿主绑定的 Reader／Writer；缺失或停用时返回明确 unavailable，包使用无记忆的默认流程。写入失败不得显示已保存。

初版桌面在 main 注入受限接口。Worker 需要时通过宿主窄消息桥代理同一接口，不持有数据库连接、全局管理器或任意 namespace。端口分发与工具 Schema 分开：模型可见的 ID／内容不包含内部授权句柄。

能力禁用仍在下次启动生效；当前运行期间不提前撤销。实际卸载／激活失败时撤销句柄并阻止迟到提交；已保存偏好保留，用户可在记忆管理页删除。删除业务资源时由包显式调用已绑定的来源失效／资源清理接口，不能由 Base 猜测业务删除。

首版以 Chat 作为真实消费者；用两个最小 SDK 夹具验证同名偏好不串用、只读句柄拒写、端口缺失可运行。公司调研是否实际接入由其业务需求另行决定，不为演示增加用户流程。

## 10. 存储、资源与观测

首版本地表位于现有 deepfield.sqlite，由宿主创建 `base:memory` Database 视图并迁移；记忆表、来源关联、revision、抑制记录与处理游标归 Memory。共享连接便于与来源删除原子提交，namespace 不代表物理隔离。

后台任务不保存重复完整对话，保存来源引用、版本和游标；进程结束后的未完成作业标记 interrupted，不自动重发状态不明的模型请求。下次只处理新的窗口或用户明确重试，避免重启引发重复费用。

首版上限：单条正文 2,000 字符、摘要 120 字符、适用条件 300 字符；每个 owner 最多 2,000 条当前记录，包含冲突、已过期和已被替代但仍保留的条目，修订历史另受每条 5 版限制。达到容量时停止新增自动记忆；手动新增返回容量原因，更新和删除仍可进行，管理页支持整理失效条目。不静默淘汰用户确认内容。以上限制需要边界样本验证，不代表性能指标。

提炼输入／输出限制、调度时机与模型快照由调用方政策提供。全应用自动提炼最多 1 个在途；异步等待不持有数据库事务。假模式提炼使用本地固定响应；不应从后台路径意外调用真实模型。

Trace 使用既有 task/stage 类别与 memory.extract／memory.commit／memory.recall 等固定阶段，关联 operationId、来源版本和模型 attempt；默认不记录记忆正文或全文检索词。Usage 复用实际调用计量；直接存取和检索无 LLM 消耗。

## 11. 验收与后续边界

首版必须证明：

- 用户明确记住的背景和偏好在新对话目录中可发现，跨语言提问可按目录取明细；编辑后旧值不再出现。不相关任务不把目录背景强行写进答案。
- 自动候选有真实来源，不能仅凭助手文本／网页指令创建全局用户规则。
- 不同 owner／scope、两个能力包、按 ID 越界与撤销后的句柄均受约束。
- 直接写入无模型调用；提炼真实请求只计一次 Usage；Fake 路径零外部请求。
- 同源重复提交幂等；并发修订、删除、关闭学习、删会话后迟到结果不复活记忆。
- 记忆损坏或提炼失败不阻断普通 Chat，显式写入失败不报成功。
- SDK 缺失或停用时包正常使用默认流程，移除全部能力不影响 Chat 的 Memory。

行为验证使用少量固定的中英文偏好改写、冲突、范围和遗忘用例，再做跨会话真实旅程；不以表读写或构建通过代替效果验收。未命中和误召回分别保留，不用放宽判准取得通过。

后续 Compact 消费记忆引用和最新版本，不把摘要自动当作事实；多 Agent 通过宿主取得任务所需 Reader 和可选候选提交口，主 Agent 或宿主策略控制长期写入。跨 Agent 调度、共享预算和完整执行恢复在后续设计中完成。
