# 统一公司调研队列实施计划

用户已确认对话中的设计并要求立即开发；主 Agent 规划、验收，子 Agent 实施。

## 已批准设计

- 全局单一串行调研队列；单个提交加入一项，批量加入多项，运行期间可追加至队尾。
- 按 companyId 全局去重（跨主题也不能同时调研）；pending/running/暂停待恢复期间拒绝重复，终态后允许再次入队。
- 每任务独立保存 itemId、companyId、研究参数、执行模式（新调研/失败重试/仅二轮重试）、原runId（如适用）。任务用独立entryId，不能用companyId作为历史任务身份。
- 单个、批量、重试均经同一调度，沿用已有执行器与失败记录规则；二轮重试只执行二轮。
- 统一等待/收集资料/整理结果提示；单公司取消只取消该项，列表取消队列终止当前并清空等待，已完成结果保留。
- 浏览其他公司的旧报告不得反复加载详情、禁用导出或清空导出对话框。
- 保留配置预检、资料补全等待、恢复/暂停、终态队列清理；已有持久化队列兼容读取。

## 约束

- 当前 develop 有用户未提交修改，保留所有原有修改，不commit/merge/push、不重置。
- 不调用真实Provider、不修改用户数据库、不启动Electron；仅必要功能测试、typecheck/build，根Agent打包。
- 继续复用现有模块，不增加第三方依赖，不扩展成通用任务平台。
- 分批提交含重复公司时不静默遗漏：UI禁选并提示，服务端原子校验拒绝竞争产生的重复。状态为cancelling时拒绝追加。
- 队列范围全局，公司列表进度按当前主题展示，取消队列明确表示整个队列。

## 实现说明

- 持久化仍复用 `company_research_batches` 快照；新快照的每个 entry 保存独立 `entryId`、`itemId`、`mode` 与可选 `originalRunId`。读取旧快照时按原 `state.itemId` 和既有 run 信息归一化，不新增数据库迁移。
- `companyResearch.start/retryFailed/retryStructuring` 的公开操作统一委托全局队列；研究 service 保持执行器职责。队列通过 owner callback 在创建或重试 run 的同一事务中保存 run ownership。
- 队列按 active company 全局去重；终态 entry 不阻止同公司再次加入。列表按当前主题投影进度，批量选择和公司详情则使用完整队列判断全局占用。
- 单项取消由 `entryId` 定位，只终止该 entry；等待中的 retry 不删除原失败报告。整队取消仍使用 `batchId`，并明确清空所有等待项。
- 报告 hook 只响应当前 item/company 的研究事件；其他公司的 raw/tool/state 事件不会触发详情重载，因此不会使 Word 导出按钮或已打开的导出对话框闪烁。
