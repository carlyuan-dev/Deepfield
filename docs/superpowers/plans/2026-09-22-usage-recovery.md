# 用量提示、恢复与稳定统计实施计划

> 用户已确认统一设计和统计补充，并明确要求开始开发。采用子 Agent 实施、主 Agent 复核，必要测试后直接打包。

## 目标与约束

- 正常运行不警告；待写入超过 3 秒仅灰字同步状态。
- LLM 看板排除 running 以及终态失败/取消/中断且所有 token 指标为空的记录。成功但未知用量计请求数；终态已有任一 token 指标（包括明确 0）保留。Search 按实际发起次数保持不变。
- 所有总览、趋势、模型选项和 Provider 汇总使用同一统计口径；提示独立从原始账本生成。关闭提示不得改变任何可见统计数值。
- 无用量终态异常：X 删除当时快照的记录，按版本与可删除条件复核；已知用量或成功未知用量：X 仅持久化确认。新异常不可被旧快照确认。
- 当前存储/传输故障红框可修复/收起；修复后自动消失，无法补回的历史缺口转可确认黄框。收起保留单行状态和修复入口。
- 修复只探测本地存储与现有 IPC，并重投仍保留的用量事件，不重发业务、不调用 Provider、不关闭/重启 Worker、不调用关闭队列的 flush。
- 失败待投递记录有界保留；同请求修订合并，幂等重投，旧事件不能覆盖新用量。队列溢出/退出后不可恢复的记录如实标记缺口。
- 旧累计计数不代表当前故障；只有当前检查失败或持续写入/传输失败才能红框。异常退出本身不警告。
- 无用量异常沿用 30 天/1000 条保留；确认元数据随记录清理，独立历史提示有界保留，不删除正常用量。
- 不修改用户数据、配置、Key；不合并提交推送；保留现有未提交修改。必要局部测试+typecheck+build，禁止 GUI 启动和真实 API 测试。

## Task 1：统一实现与定向测试

- [ ] Base Usage contracts/query：明确计入统计与通知投影、确认/修复接口，不导入上层。
- [ ] Persistence usage repository/migrations：确认状态、存储读写检查、历史事件/确认有界保留；不重置真实账本。
- [ ] shared/worker/main usage runtimes：有界可恢复待投递、独立 retry 操作、当前状态与历史缺口分离，安全的 Worker 恢复 IPC。
- [ ] Contracts/preload/main IPC：白名单参数及返回值校验；新接口贯通，失败返回真实错误。
- [ ] Settings UsageDashboard：按规则呈现黄/红/灰，关闭/修复加载与失败、最新筛选刷新、防重复点击。
- [ ] 更新 docs/base/base.usage.设计文档.md，明确新章节覆盖旧统计/健康规则。
- [ ] 定向验证：删除异常前后总览/趋势/Provider/模型选项不变；运行中不警告；成功未知和部分用量确认后账本保留重启不重现；新异常不被旧快照覆盖；写入失败后本地补写幂等；当前故障修复与历史不可恢复缺口分离；并发切页不覆盖新筛选；所有队列/元数据有界。

## Task 2：复核与交付

- [ ] 主 Agent 检查差异，独立 reviewer 按批准规则审查关键状态/并发/清理边界。
- [ ] 必要测试与 typecheck/build 成功后打包到现有测试版目录；确认目标未运行，不能覆盖运行中的 app。
- [ ] 本轮 Capability 内容未变，不替换已安装能力；如构建比较显示变化先核对来源。暂存不得放入 capabilities 扫描目录。
- [ ] 交付测试 app 路径和最小手测清单，明确不可恢复数据不补零。
