# Chat 连续任务与公司补全修复计划

> For agentic workers: use superpowers:subagent-driven-development。用户已确认本轮范围并要求持续实施、必要测试后打包；由主 Agent 规划复核，子 Agent 开发。

**Goal:** 解决中文输出漂移、交互旧轮次重复操作、连续任务逐项确认，以及删除公司后进度与未知资料重试问题。

**Architecture:** Chat 持有真实用户授权和执行生命周期；Capability 只声明操作和业务资源范围。不得在通用 Chat 中硬编码公司字段。复用既有确认卡、表单、执行回执和 Pi Loop。

**Spec:** 用户 2026-09-24 已批准的短设计；本文件固化边界，相关设计文档由各任务同步更新。

## Global Constraints

- 在现有 develop 脏树工作，保留所有既有变更。不提交、合并或推送，不修改真实业务数据，不发真实模型/Search 请求。
- 授权只来自真实用户入口，只覆盖当前任务；删除必须显式纳入范围。模型和工具结果不能自行批准或扩大范围。
- 新任务、取消、失败停止、完成和重启不继承任务授权；表单人工修改与过期轮次不能偷偷使用旧授权。
- 自动执行仍走同一协调器、校验、回执和页面联动，不直连业务函数绕开交互约束。
- 用户可见回复语言以真实人类消息为准，自动恢复事件不作为语言参照；不增加每轮额外翻译模型调用。
- 只做必要定向测试、一次最终类型检查/构建，子 Agent 不再派生。并行任务严格按文件职责隔离。
- 完成打包到 release/mac-arm64/Deepfield.app，同步实际加载的 Capability 包；覆盖前确认应用已退出。旧安装包可恢复备份，不动 DB/密钥/报告。
