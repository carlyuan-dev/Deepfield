# Deepfield Capability A：单家公司自主调研设计

日期：2026-09-09
状态：设计与书面规格均已确认，进入实施

## 1. 目标

当前阶段性目标是跑通单家公司调研报告的最小线路：用户从行业中的公司详情页启动一次调研，独立 Research Agent 使用 DeepSeek 网页搜索生成流式报告，成功后保存为一个历史版本。

本阶段最终目标不是完成整套证据验证系统，而是将真实公司的单次调研效果交给记者确认。只有记者认为报告方向、信息密度和来源选择具备实际价值，单家公司初步调研阶段才算通过；在此之前优先调整 Prompt 和必要交互。

## 2. 当前基线

当前代码已经具备：

- 全局唯一 Company 和行业—公司关联；
- 行业、公司列表和公司详情页面；
- Main、Utility Process、Renderer 之间的流式 Agent 通信；
- macOS 加密 DeepSeek Key 存储；
- DeepSeek Responses API 联网搜索路径；
- Chat 和 Capability 可独立收展的页面壳层。

普通 Chat Conversation 与 Capability 业务状态彼此独立。单家公司调研不能伪装为隐藏 Chat，也不把研究报告写入 Conversation 历史。

## 3. 用户路径

入口固定为：

```text
行业研究 → 行业 → 公司列表 → 公司详情 → 开始调研
```

公司列表继续负责公司管理。第一版不在公司列表提供批量调研入口。

### 3.1 启动调研

公司详情页右上角显示：

- 没有成功报告时：“开始调研”；
- 已有成功报告时：“重新调研”。

按钮打开轻量悬浮窗，包含：

- 调研时间范围：必填文字，默认“重点调研近一年，必要的公司背景不限时间”；用户也可以填写“一年内”“近三个月”或“不限时间”；
- 补充要求：选填多行文字；
- 取消；
- 开始调研。

第一版不显示联网开关和 Skill 选择器。公司调研固定使用 DeepSeek 网页搜索，并由 Capability 隐式使用内置研究 Prompt。

### 3.2 调研中

调研开始后悬浮窗关闭，公司详情页显示：

- “正在联网调研…”；
- 已运行时间；
- 当前流式报告草稿；
- “取消调研”。

DeepSeek 调用是一个无法可靠换算为百分比的外部任务，因此不显示虚假进度百分比或人为编造的固定步骤。

关闭 Capability、展开 Chat、切换行业或公司不会取消调研。任务在应用仍运行时继续；用户返回该公司时可重新看到当前状态和内存草稿。用户可以在调研期间继续使用普通 Chat。

### 3.3 调研完成

成功后默认展示最新报告。顶部提供按完成时间选择历史版本的控件，例如：

```text
2026-09-09 16:30 · 重点调研近一年
```

报告以安全纯文本显示，保留段落和换行，完整的 HTTP/HTTPS 网址自动变成可点击链接。模型返回内容不作为 HTML 执行。

“重新调研”默认带入最近一次成功调研的时间范围和补充要求。每次成功调研创建一个新版本，不覆盖旧报告。第一版不提供版本删除、差异比较或正文编辑。

## 4. Research Agent 边界

每个 ResearchRun 对应一个任务级 CompanyResearchAgent。它类似子 Agent，但不需要 LangGraph 或通用 Agent Supervisor：

- 每次任务拥有独立上下文；
- 不读取普通 Chat 历史；
- 不复用其他公司或其他行业的 Agent 上下文；
- 完成、取消或失败后释放 Agent；
- 长期保存输入条件和最终报告，不保存 Agent 对话或内部推理。

第一版通过公司详情页直接调用 CompanyResearchService。主 Chat 暂不启动或操纵该 Capability。以后接入主 Agent 时，复用同一个服务入口，而不重写调研逻辑。

整个应用同一时间最多运行一个 CompanyResearchAgent。其他公司在任务运行期间不能再启动调研。批量公司调研将在单公司效果通过后再设计顺序队列。

## 5. 输入上下文

Research Agent 只接收本次任务需要的数据：

- 当前日期；
- 公司名称；
- 公司国籍或地区；
- 当前行业名称；
- 行业研究范围；
- 该公司在当前行业中的候选备注；
- 用户填写的调研时间范围；
- 用户补充要求。

同一家公司在不同行业中的调研属于不同上下文和不同历史版本。例如，小米在“智能眼镜”和“消费电子”中的 ResearchRun 相互独立。

## 6. DeepSeek 调用与 Prompt

CompanyResearchAgent 使用 DeepSeek Responses API：

- 模型沿用当前配置的 `deepseek-v4-flash`；
- `stream: true`；
- 提供 `web_search` Tool；
- `tool_choice` 强制选择 `web_search`；
- `max_output_tokens: 32768`。

`32768` 是首轮效果测试的上限，不是固定产品常量。DeepSeek 将推理和可见输出共同计入该限制，因此首轮保留较多余量；后续根据真实 token 使用量、报告长度和等待时间调整。

内置 `company-research-v1` Prompt 只约束必要底线：

1. Agent 自主决定调研方向、关键词和搜索顺序；
2. 使用网页搜索形成结论；
3. 输出中文调研报告，不展示内部计划、推理或检索过程；
4. 报告结构、重点和详略由 Agent 自主决定；
5. 每项重要结论只保留一个最合适的来源，紧跟结论显示完整网址，格式为 `来源：https://……`；
6. 来源根据发布责任主体、内容与结论的匹配程度和直接性选择；优先公司官网、公告、财报、政府或监管机构、官媒及可信专业媒体；
7. 同一结论存在多个转载或转述来源时，只保留最强来源；
8. 找不到可靠来源的内容不写成确定结论，可以作为尚未确认事项说明；
9. 报告末尾不重复堆砌来源目录。

来源判断不按平台名称机械分级。例如，同一消息同时出现于澎湃新闻、普通百家号和个人微博时，优先澎湃新闻；如果百家号账号能够确认属于目标公司，则按公司官方责任主体判断。

第一版输出是一份待后续验证的初步调研报告。它不是已验证事实库，也不是记者可直接发布的最终稿。

## 7. 数据模型

新增 `ResearchRun`，同时绑定行业条目和公司：

```text
ResearchRun
  id
  itemId
  companyId
  status: running | completed
  timeScope
  customRequirements?
  reportText?
  createdAt
  completedAt?
```

数据库中的 `(item_id, company_id)` 外键指向行业—公司关联。删除某公司与该行业的关联时，级联删除该关联下的全部 ResearchRun；该公司在其他行业中的报告不受影响。

`running` 记录中的 `reportText` 为空。流式草稿只由 Main 进程的活动任务状态持有。成功时完整报告、完成时间和 `completed` 状态一次性写入。历史列表按完成时间倒序，并使用稳定的同时间排序规则。

## 8. 运行状态和失败清理

用户长期可见的稳定状态只有：

- 无报告；
- 调研中；
- 已有成功报告。

`failed` 和 `cancelled` 只作为一次性界面结果，不保存为长期 ResearchRun 状态。

运行规则：

1. 开始时创建 `running` ResearchRun；
2. Main 持续消费 Utility Process 事件，并在内存中保存当前流式草稿；
3. 成功时事务化保存完整报告；
4. DeepSeek 调用失败、用户取消、协议异常、输出为空、返回 `response.incomplete` 或最终数据库写入失败时，删除本次 ResearchRun 和内存草稿；
5. 应用启动时删除上次异常退出遗留的全部 `running` 记录；
6. 新任务失败时，已有成功报告保持不变。

DeepSeek 调用失败统一表现为 LLM 当前不可用，不设计离线生成或其他 Search Provider 降级。

## 9. 事件与取消

研究请求和事件使用独立于 Chat 的契约，通过现有 Utility Process 传输：

```text
company-research.run
  → started
  → text_delta × N
  → completed | failed | cancelled
```

所有事件以 `runId` 和传输请求 ID 关联，不能进入 Chat reducer 或 Conversation 消息表。

用户点击“取消调研”后，Main 发送受控取消消息，Utility Process 中止对应 AbortSignal。关闭或离开页面只改变订阅和布局，不发送取消消息。应用退出时中止活动任务，并由下次启动清理未完成记录。

## 10. 模块划分

最小实现新增或扩展：

- Contracts：ResearchRun、启动输入、Worker 请求与事件、Desktop API；
- Persistence：migration、CompanyResearchRunRepository；
- Application：CompanyResearchService，负责全局单任务、持久化和清理；
- Utility Process：CompanyResearchAgent、研究请求路由和取消；
- Main/Preload：IPC、事件转发、活动任务快照；
- Renderer：启动弹窗、运行状态、流式草稿、报告正文和历史版本选择。

CompanyResearchAgent 可以复用当前 DeepSeek 联网 Agent 的 SSE 解析和安全错误处理机制，但拥有独立的 Prompt、请求契约和事件类型。不得通过构造隐藏 Conversation 来复用 ChatService。

## 11. 本切片范围

本切片交付：

- 公司详情页直接启动一次自主联网调研；
- 流式查看报告；
- 取消和彻底失败清理；
- 成功报告版本保存；
- 历史版本切换；
- 一个全局活动调研限制；
- 真实公司效果测试所需的最小界面。

后续切片再处理：

- 主 Chat 启动 Capability；
- 批量公司队列和公司级进度；
- 用户选择或绑定 Skill；
- 原子事实拆分、来源分级、网页访问和 Search Provider 二次验证；
- 报告编辑、删除、差异比较和导出；
- 增量调研、公司介绍刷新及版本回滚；
- 本地附件和资料库参与调研。

## 12. 有限测试策略

自动检查只覆盖三个高价值主路径：

1. 持久化与服务：成功形成新版本；取消或失败后清理本轮记录；
2. Agent 适配：独立上下文、强制网页搜索、流式完成和截断失败；
3. Renderer：从公司详情启动、看到流式草稿、完成后切换历史版本。

小任务只运行对应聚焦测试和类型检查。阶段检查点执行一次 Fake 功能 Smoke。当前不扩展全量排列组合、覆盖率、重复构建或大规模 E2E 矩阵。

## 13. 验收门

### 13.1 工程线路验收

- 公司详情可以启动真实的独立调研任务；
- 调研强制使用 DeepSeek 网页搜索；
- 页面可见流式内容，离开页面后任务继续；
- 成功报告在重启后仍存在并可按时间切换；
- 取消、失败和异常退出不留下未完成报告；
- 普通 Chat 在调研期间仍可使用；
- 同一时间不能启动第二个公司调研任务。

### 13.2 产品效果验收

工程线路跑通后，先由项目开发者使用至少两家公司各运行一次，并对其中一家重新调研一次。根据结果调整 Prompt、输出上限和必要交互。

达到稳定候选效果后，将一次真实公司的调研结果交给目标记者确认，重点评估：

- 是否覆盖记者真正需要的信息方向；
- 信息密度和篇幅是否可用；
- 重要结论是否只有一个最佳来源；
- 来源是否真正支持对应结论；
- 报告是否值得作为后续证据验证阶段的输入。

记者确认单次调研报告具有实际使用价值，才视为本阶段最终完成，并进入原子事实和证据验证设计。
