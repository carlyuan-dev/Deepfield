# Deepfield 迭代式 MVP 总设计

日期：2026-09-07

状态：当前有效设计，已通过对话评审；开发状态更新至 2026-09-09

优先级：本文件取代早期规格中尚未实施的 Capability A 流程、Provider 选型门槛和后续开发顺序。P1 已验收实现与 P2 已落地的 Tool Platform 代码继续作为技术基线。

## 1. 产品目标

Deepfield 是供一名财经记者私人使用的 Apple Silicon macOS 桌面应用。产品首先是一个通用主 Agent；Capability 是主 Agent 可以启动、用户也可以直接打开的业务功能。当前目标是尽快形成可安装、可实际使用、可根据记者反馈迭代的最小版本。

开发采用连续的小型垂直切片。每个切片先完成一个真实用户路径，交给用户体验，再根据实际问题设计下一步。

## 2. 当前架构基线

已实现能力包括：

- Electron、React、TypeScript 桌面壳层及 Apple Silicon 本地打包；
- 独立 Conversation、消息、行业条目、全局公司及行业—公司关联的 SQLite 持久化；
- macOS 加密密钥存储；
- Electron Utility Process 中的 Pi Agent；
- Conversation-first Chat、Capability 画布和收窄 Chat 栏三种界面形态；
- DeepSeek 联网搜索开关、手动 Pi Skill、流式 Tool 调用状态展示；
- 主 Agent 的时间、计算、时区和 Conversation 读取工具；
- 行业条目创建、编辑、批量删除，以及公司手动管理、长文本识别导入、跨行业复用和零引用清理；
- 版本化 Tool Registry、Tool Runner、权限、预算、审计和 Pi Tool Adapter；
- 安全网页访问、链接检查、HTML/PDF 解析及多个 Search Provider 适配器。

这些是后续功能可按需调用的基础设施。当前产品进展以用户能否完成真实任务为主要判断标准。

主 Agent 当前不暴露网页抓取、网页解析或链接检查 Tool；联网 Chat 统一走 DeepSeek
联网搜索。网页访问与 Search Provider 基础设施继续保留给 Capability 的证据验证阶段。
本地附件目录已预留，但拖入文件、附件读取和文件检索尚未形成可用的主 Agent 路径。

## 3. 通用主 Agent

主 Agent 支持四类交互：

1. 普通 Chat；
2. 用户通过按钮开启的 DeepSeek 内置联网搜索；
3. 用户手动选择的 Pi Skill；
4. 调用 Deepfield 原子 Tools；
5. 启动有持久化业务状态的 Capability。

Chat 输入框提供“联网搜索”按钮，默认关闭。用户打开后，本轮消息必须执行联网搜索，界面展示联网状态，回答中的来源可点击。Chat 同时提供手动 Skill 选择器，选中的标准 Pi `SKILL.md` 只作用于当前一次发送。Capability 可以拥有独立的联网设置。

行业公司发现既可以在外部通用 Agent 中完成并粘贴到 Deepfield，也可以直接在 Deepfield Chat 中完成。Chat 结果可以一键送入公司候选整理页面。

## 4. Capability A 的逐步形态

### 4.1 行业和公司候选整理

用户创建行业项目后，可以：

- 粘贴外部 Agent 的行业公司调研结果；
- 粘贴或输入自然语言公司名单；
- 从 Deepfield Chat 导入联网回答；
- 手工新增、修改或删除公司。

LLM 从文本中提取公司名称和一条简短候选备注。备注用于人工筛选，不作为正式事实证据。公司由用户确认后进入项目名单。公司基础实体全局唯一，可以属于多个行业项目；行业相关研究内容按项目保存。

### 4.2 单家公司初步调研

每次调研创建一个 `ResearchRun` 和一个任务级 Research Agent。Agent 运行时读取公司、行业、用户勾选字段、自定义要求、本地资料、Skill、调研时间范围和联网设置。

系统通过 Prompt 约束目标、时间和输出格式；Agent 自主规划调研方向、关键词和搜索过程。输出是一组原子事实，而不是直接生成完整报告。每条原子事实包含：

- 一条可以独立判断真假的事实表述；
- Agent 自主形成的所属方向；
- 可选的事件时间；
- 关键词；
- 候选网址；
- 简短说明。

Research Agent 以一次调研任务为上下文边界。运行结束后释放 Agent，长期保存的是结构化事实、证据、调研摘要和用户确认记录。后续增量调研由新的任务级 Agent 读取既有成果，不重复携带完整历史对话。

### 4.3 原子事实验证

初步调研结果统一进入待验证状态。验证阶段以候选网址为起点：访问网页、提取正文、识别发布责任主体，并判断网页内容与事实语义是否匹配。证据缺口再使用独立 Web Search 补查。

系统根据证据情况显示四种颜色：

| 颜色 | 含义 |
| --- | --- |
| 黄色 | 网页可访问、内容支持事实，发布者具有明确且可信的责任主体 |
| 橙色 | 网页可访问、内容支持事实，但发布者权威性或责任强度一般 |
| 红色 | 没有匹配证据、网址失效、正文不支持事实或存在明显冲突 |
| 绿色 | 用户已确认该事实可用于后续写作 |

来源等级由发布主体决定，而不是由平台决定。公司官网、财报、官方机构以及可以确认归属于公司的官方账号属于可信责任主体；普通用户或身份不明账号即使位于大型平台，也按一般来源处理。权威网页若不支持具体表述，该事实仍为红色。

用户可以确认黄、橙、红事实。红色事实由用户自行核实后也可以变绿，内部记录“用户自行核实”；该内部说明不写入最终报告正文。

### 4.4 报告和公司介绍

用户完成原子事实审核后，系统仅使用绿色事实生成首次公司调研报告，并自动创建公司介绍 V1。

后续增量调研按时间批次保存。每轮读取上次总结和已确认事实，聚焦上次截止时间之后的新发现、更新、纠正和冲突。默认输出增量报告，历史批次保持可查看。

公司介绍是持续维护的当前档案。首次调研自动创建；后续增量报告确认后询问用户是否刷新。用户也可以手动点击刷新。刷新以当前公司介绍底稿和最新确认事实生成新版本，用户手写内容只在用户明确确认刷新后参与更新。所有版本保留并支持回滚。

## 5. 联网和搜索成本原则

初步调研默认启用 DeepSeek 内置联网搜索，用户可以关闭。模型侧联网结果属于研究线索，需经过 Deepfield 的证据验证后才能成为系统证据。

验证阶段优先直接访问候选网址，再使用独立 Search Provider 补足证据。可刷新的免费额度优先，一次性免费额度随后使用，Serper 位于免费路由末位。所有免费额度耗尽后，系统在下一次实际付费调用前请求用户确认。

搜索策略和调用数量根据真实调研效果逐步调整。Provider Benchmark 不再作为后续产品功能的前置门槛。

## 6. 分阶段交付顺序

当前交付状态与顺序为：

1. **已完成**：Chat-1 通用对话、短期记忆、历史恢复、DeepSeek 联网按钮、手动 Pi Skill 和流式回答；
2. **已完成**：Chat-2 最小 Tool 集与客户端 Tool 调用状态展示；
3. **已完成**：行业创建与公司候选整理；
4. **当前下一切片**：单家公司自主初步调研；
5. 原子事实证据验证；
6. 用户审核、首次报告和公司介绍；
7. 增量调研、时间记录、介绍刷新和回滚；
8. Chat-3 拖入文件、资料库和最小文件检索作为独立切片按真实需要插入，不阻塞当前公司调研主路径。

每个阶段在用户实际体验并验收后，才进入下一个阶段的详细设计和实施。

## 7. 有限功能测试策略

本项目是单人使用的个人应用，工程策略以快速形成可用功能为先：

- 每个切片使用少量代表性问题或操作验证主路径；
- 自动化测试集中在密钥安全、数据持久化、付费边界等高风险位置；
- 普通交互和模型效果以人工功能测试为主；
- 实际发现 Bug 后，为该 Bug 增加最小复现和针对性回归测试；
- 一个小任务完成时运行相关功能测试；
- 一个阶段完成时运行一次类型检查、构建和应用启动 Smoke；
- 验收报告强调用户路径和实际结果，不以测试数量、覆盖率或边界排列组合为目标；
- 现有测试继续作为回归资产，新增工作控制测试增长。

DSH 任务只描述当前切片的目标、用户路径、接口、最少验收条件和最少功能测试。后续阶段在各自开始时再展开。
