# Chat 连续性、工具历史与搜索日期降级设计

## 目标

修复 Chat 在切换对话时丢失进行中回复和工具过程的问题，允许用户删除已完成或空闲对话，将工具执行记录永久关联到对话，并解决 Search Provider 不支持原生日期范围时的联网失败。

## 产品行为

- 侧栏对话项悬停时显示删除入口；删除前二次确认。
- 正在生成的对话不可删除，界面提示“对话生成中，请等待完成后再删除”。本轮不新增 Chat 取消协议。
- Agent 在后台运行时，用户可切换对话；切回后立即看到此前流式正文和工具状态，后续事件继续实时更新。
- 重新打开历史对话时恢复工具名称、最终状态、耗时与安全错误码；不保存密钥、完整请求头或不受控网页正文。
- 相对日期继续先转换成绝对日期。以 2026-09-14 的“最近三个月”为例，约束必须是 `2026-06-14` 至 `2026-09-14`。
- 支持原生日期过滤的 Provider 使用结构化 `timeRange`；不支持的 Serper、秘塔、智谱把同一绝对日期写入查询词，作为明确的查询词日期约束，而不是丢弃日期或伪称使用了原生过滤。
- `maxResults` 对模型可选，缺省时使用 5，避免非关键参数遗漏导致整个调用在本地失败。

## 架构

Renderer 中只保留一个长期存活的 Chat 状态控制器，并按 conversationId/requestId 保存各对话的已加载消息、流式草稿和工具活动。切换对话只改变当前选择，不再通过 React `key` 销毁控制器。

持久化层给 Chat 消息增加可选 requestId。用户消息在发起请求时即保存该 requestId，助手终态消息复用它；现有 `tool_executions.trace_id` 已等于 requestId，因此历史读取可安全地把工具审计记录装配回对应回复。删除对话时，在一个事务内清理该对话 requestId 对应的工具审计记录，再依靠外键级联删除消息。

Search 工具在统一适配层按当前 Provider capability 生成有效请求：原生支持时透传绝对日期范围，不支持时构造包含绝对起止日期的有效 query 并移除结构化 `timeRange`。工具输出应暴露实际 query，使 Agent 能判断这是查询词约束。

## 边界

- 不持续把每个 token 写入 SQLite；进行中的草稿在当前应用会话内由全局 Renderer 状态维持。
- 应用退出仍由最终完成事件持久化助手正文；本轮不实现崩溃恢复。
- 工具历史复用审计表，不在 message content 中复制一份工具 JSON。
- 删除只允许空闲对话；不新增隐式取消或强杀 Agent。

## 验收

1. 联网回答生成中切换到另一对话再切回，已经出现的正文和工具活动仍在并继续更新。
2. 完成后重启或重新打开对话，工具记录仍可显示。
3. 空闲对话可确认删除；生成中的对话无法删除且有明确提示。
4. Serper、秘塔、智谱收到包含绝对起止日期的查询词且不再因 `timeRange` 报 `invalid_input`；百度、Tavily继续收到原生 `timeRange`。
5. Search 连接诊断、普通 Chat 与一轮公司调研共用同一 Search Provider 适配行为。
