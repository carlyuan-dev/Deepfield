# Deepfield Capability A：行业条目与公司名单设计

日期：2026-09-08
状态：已实现，等待用户手测

## 目标与边界

“行业研究”是独立于 Conversation 的 Capability。用户在 Capability 内依次浏览调研条目列表、某条目的公司列表和某公司详情；Chat/Capability 收展不会销毁当前 Chat。主 Agent 当前不会读取、创建或调用 Capability，Agent/Capability 编排留到下一阶段。

## 调研条目

首页按最新创建时间展示行业，顶部提供“添加行业”和“删除行业”。创建使用表单弹窗；每个行业行右侧提供灰色“编辑”按钮并以悬浮窗编辑必填行业、选填研究范围和备注。保存后标题、摘要和列表状态立即更新。

“删除行业”进入列表级批量选择，可勾选、取消或确认；确认后再显示危险操作对话框。行业内部页面不提供行业编辑或删除。一次批量请求在同一 SQLite 事务中删除全部选中行业及其关联，并清理因此失去最后一个行业引用的公司；任一步失败则整体回滚。Conversation、消息和 Tool 审计保持不变。

## 公司列表与详情

公司页顶部提供三个独立入口：

- “添加公司”：连续录入公司名称、国籍/地区和候选备注，形成可删除的待确认草稿，确认后批量加入；
- “批量删除”：在页面内选择、全选或清空，二次确认后一次移除所选关联；取消确认保留选择；
- “一键导入公司”：从粘贴文本识别可编辑候选，确认后批量加入。

每个公司行可进入公司详情，并有默认灰色、悬停变危险色的独立删除叉号。选择模式下点击公司只切换选择，不进入详情。单条删除、批量删除和详情页删除均有取消与确认；失败时保留当前页面和选择并显示固定友好错误。

详情首版只展示公司名称、国籍/地区、候选备注和中性占位“公司调研内容将在下一阶段生成”，不生成或虚构研究内容。

公司基础实体按 trim、Unicode NFKC、空白折叠和小写后的名称全局唯一；候选备注属于条目—公司关联。单条移除、批量移除或删除行业均在同一事务中清理零引用公司；仍被其他行业引用的公司继续复用。

## 长文本识别

Renderer 使用 `chunkRecognitionText`：单块最多 4000 Unicode code points，总文本最多 48000 code points，优先在空行、换行和句末切分，超长段落硬切且不拆代理对。超过总上限时在调用 API 前显示固定错误，调用次数为零。

识别按块顺序调用 `recognizeCompanies(itemId, chunk)`，不并发突发。内部在每块成功后累积候选，并按与持久层一致的规范名跨块去重、保留首次字段；某块失败后停止后续调用，保留原文和已成功候选，重试时不重复已成功块。界面只显示“正在识别…”、识别结果或通用失败/重试，不显示块数、段号、游标或续跑位置。修改源文本会重置旧进度与候选。

识别期间源文本锁定；关闭或取消仍可用。进行中的请求不能强制中止，但 run token 会阻止关闭后的状态更新和下一块启动。全部完成后候选可编辑、删除并确认导入。开发与自动检查使用 Fake recognizer；真实 DeepSeek 长文本识别只做用户手测。

DeepSeek 请求由 Main 发出，使用 JSON object mode、2048 token 输出预算和识别专用 20 秒超时，并要求候选备注保持极简；连接检查与标题生成仍使用默认 7 秒超时。该预算基于 33 家公司样例在 512 tokens 下以 `finish_reason=length` 截断的真实诊断提升。Key 只由 Main 的加密 SecretStore 读取，不进入 Renderer、日志或数据库。
