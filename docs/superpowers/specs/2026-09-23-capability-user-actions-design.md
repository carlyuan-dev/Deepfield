# Chat 功能说明与 Capability 操作覆盖设计

状态：2026-09-23 用户已确认聊天中完整范围并明确要求进入开发。本文将已批准方案落盘，不另扩大功能。

## 目标

- `/help` 确定性直返固定模板；自然语言功能总览询问进入普通模型 Loop，由只读“查看可用功能”工具返回同一模板：工具名称与用途、能力名称与可执行功能；没有协议、参数、版本、权限细节或结尾追问。
- 目录来自本轮实际可调用工具及本次启动 ready 的 Capability，不另维护独立功能清单。直接搜索开关和 Capability 自身资源影响独立。
- 模型内部保留准确 ID、枚举、引用、游标，普通最终回答只呈现名称、业务状态、日期、结果和有价值的风险；用户明确要求技术细节时可按需解释，禁止全局正则删除代码/URL/正常业务内容。
- 确认卡显示中文业务参数，不显示原始 JSON。可信确认绑定原始规范化参数，不使用显示文本授权。
- 公司调研页面业务操作全部具备 Chat 语义入口，复用现有服务。纯 UI 上一步/下一步/全选/关闭不是 DOM 点击工具：通过语义导航、草稿参数及任务控制表达。

## 已确认的业务覆盖

主题：查看、新建、编辑、删除（含批量）。公司：列表、详情、添加、文本识别与导入、编辑共享基本信息、从主题移除、补全重试、主体确认。调研：单个/批量提交、按公司覆盖输入、失败重试、只重试结构化、查询/取消/恢复队列及单任务。报告：列出、读取、打开选定版本、删除、Word 导出与内容选择。

增加包声明动作，不把内部 IPC 自动全部暴露；通用主 Agent/宿主不得包含公司业务分支。主题与公司的真实名称解析由模型查询公开目录完成，不要求用户提供 ID。公司修改是共享资料修改；公司删除实际为移除当前主题关联，必须如实显示。

## 设计

1. 保留现有 Pi Agent Loop 与 5 个通用 Capability 调用面。已有 title/description 用作用户功能目录来源；内部 bridge 工具不重复列成用户业务功能。
2. 仅 `/help` 使用确定性模板且不调用 LLM/Search。自然语言总览询问由 Pi Agent 按意图调用通用只读功能目录工具；工具从本轮可调用 ToolSet 与 ready Capability 目录生成与 `/help` 相同的文本，不额外调用模型做分类。混合具体业务请求继续办理，不由快捷规则截走。`/help` 进入正常会话持久/事件流程，不伪造工具调用或 Usage。
3. 普通回答提示明确区分技术协议与用户结果；机器参数、ID、引用和游标保留在内部调用中，默认向用户讲名称、动作、结果和必要日期。用户明确索要技术细节时可解释，不用全局正则删 UUID、代码或链接。包文档提供中文业务字段解释，不要求最终回答打印 revision/内部引用。保留来源和必要事实日期。打开成功通常一句“已打开……”，失败只讲实际原因与下一步。
4. SDK 增加可选的运行时 `presentInput(input)` 展示投影，宿主验形和限长后用于确认卡；返回 `{title, fields:[{label,value}]}`，value 为文字。不得更改确认绑定、对模型新增权限或在投影中执行写操作。包负责将 ID 解析成名称。没有展示器的旧包保留可理解、安全的后备显示，不自动执行。
5. 新增公司动作按领域分文件，通过同一 `defineAction` 生成 Schema、清单与说明摘要；公开列表/详情附中文业务信息，必要机器字段仍保留。添加公司可能触发资料补全，识别、补全、调研、重试/恢复须如实标记资源消耗；删除标记 destructive，资源消耗/破坏性请求经真实确认。
6. 单/批量/重试继续复用现有统一队列及事务回执。Chat 重试查询原调用，不另建业务调度器；批量返回可跟踪整个提交集合的 TaskRef，并且取消仅影响该提交拥有的任务，不误取消后来加入的其他任务。完整队列取消是独立明确动作。原始成功、结构化失败的报告仍可读。
7. 导出复用已有 native save dialog 与覆盖确认，模型不能传任意保存路径。取消保存返回取消而非成功。导航只在用户意图/活跃会话下执行，保留现有未保存输入保护及请求撤销。

## 验证与交付

必要离线测试：动态帮助无内部协议且随工具/启动目录变化、普通业务请求不被误识别；确认展示不改变实际绑定；新建主题/导入公司/删除授权/重试与批量回执/Word 取消走真实服务的 Fake 依赖测试。无真实付费 API，不读写用户数据。最终定向测试、typecheck、build、独立审查后打包，应用退出后同步能力包并保留备份。只在 develop，不提交/合并/推送。
